# Архитектура нулевых значений, отключённых блоков и отрицательного результата

Обновлено: 21 августа 2026 года.

Статус: рабочее правило модели. До изменения кода документ проверяется и утверждается владельцем проекта.

---

# 1. Назначение документа

Документ закрепляет единое правило для:

- выключенных параметров;
- исключённых блоков анкеты;
- прямых и обратных галочек;
- неактивных веток radio и dropdown;
- нулевых денежных и временных вкладов;
- обязательных параметров, которые нельзя обнулять;
- положительного дохода;
- отрицательного финансового результата;
- отображения убытка в отчёте.

Цель — не создавать отдельную формулу для каждого сочетания галочек, а использовать одну модель, в которой каждый параметр всегда существует и получает эффективное значение.

---

# 2. Основное архитектурное правило

> Каждый параметр постоянно существует в структуре модели. Если параметр выключен, исключён или относится к неактивной ветке, его эффективное значение равно нулю.

Формулы не удаляют такой параметр и не переходят на альтернативную математику. Они продолжают использовать общий набор показателей, в котором неактивные показатели дают нулевой вклад.

Пример:

```text
Все денежные затраты =
амортизация
+ текущие расходы
+ налог
+ эквайринг
+ фонд развития
+ резерв программы лояльности
+ стоимость собственного сайта
```

Если фонд развития выключен:

```text
Все денежные затраты =
амортизация
+ текущие расходы
+ налог
+ эквайринг
+ 0
+ резерв программы лояльности
+ стоимость собственного сайта
```

---

# 3. Сырое и эффективное значение

Для необязательного параметра различаются два значения.

## 3.1. Сырое значение

Значение, которое хранится в поле анкеты или в состоянии браузера.

Пример:

```text
Размер фонда развития: 10%
```

Даже если фонд выключен, сохранённое значение можно оставить равным 10%, чтобы пользователь не настраивал его повторно после включения.

## 3.2. Эффективное значение

Значение, которое фактически поступает в расчёт.

При выключенном фонде:

```text
Сырое значение:        10%
Эффективное значение:   0%
```

При включённом фонде:

```text
Сырое значение:        10%
Эффективное значение:  10%
```

Все расчётные формулы и весь отчёт должны использовать эффективное значение.

# 4. Типы управляющих элементов

## 4.1. Прямая галочка включения

Прямая галочка означает:

```text
галочка снята      → параметр выключен → эффективное значение 0;
галочка установлена → параметр включён  → используется выбранное значение.
```

Примеры:

- учитывать резерв времени на форс-мажоры;
- заложить фонд развития;
- заложить запас на скидку.

## 4.2. Обратная галочка — галочка исключения

Нужно закрепить отдельное понятие:

### Наименование

```text
Обратная галочка
```

### Предлагаемый ID типа

```text
exclude_checkbox
```

### Определение

> Галочка с обратным смыслом: пока она снята, блок или параметр участвует в расчёте; после установки галочки блок остаётся в структуре модели, но все его эффективные результаты становятся равными нулю.

Правило:

```text
галочка снята       → блок учитывается;
галочка установлена → блок не учитывается → эффективные результаты блока = 0.
```

Пример надписи:

```text
Не учитывать этот блок в расчёте
```

Обратная галочка не удаляет введённые значения. Они сохраняются для возможного повторного включения блока.

## 4.3. Переключатель ветки

Radio или dropdown выбирает одну из нескольких взаимоисключающих веток.

Примеры:

- работа дома / отдельное помещение;
- сайт сделал подрядчик / сайт сделал пользователь;
- учёт веду самостоятельно / нанимаю специалиста;
- налоговый режим.

Вклад активной ветки рассчитывается. Вклад неактивных веток равен нулю.

## 4.4. Управляющая галочка без денежного значения

Некоторые галочки управляют поведением интерфейса, но не являются расходом.

Примеры:

- автоподбор налогового режима;
- контекстная галочка «Живу в своём»;
- кнопки сброса.

Для них нельзя автоматически применять правило «снята — денежный параметр равен нулю». В реестре полей они должны иметь роль `service` или `switch`, а не `input`/`result`.

# 5. Обязательные и необязательные параметры

## 5.1. Необязательный параметр

Может иметь эффективное значение ноль.

Примеры:

- реклама;
- фонд развития;
- резерв скидки;
- эквайринг;
- время на клиента;
- время на продвижение;
- форс-мажор;
- отдельный каталог расходов.

## 5.2. Обязательный параметр

Не должен молча становиться нулём, если используется как основа или делитель.

Примеры:

- продолжительность съёмки;
- полное время одного проекта;
- количество съёмочных часов;
- срок службы при распределении стоимости;
- общая площадь жилья при расчёте доли рабочего места.

Если обязательное значение отсутствует или равно нулю, расчёт должен остановиться до исправления поля.

Правильное поведение:

```text
«Укажите продолжительность съёмки — значение должно быть больше нуля»
```

Неправильное поведение:

```text
молча заменить значение;
получить бесконечность;
делить на ноль;
продолжить с выдуманным значением.
```

# 6. Как правило применяется к текущей анкете

## Налоговый блок

```text
Налоги включены  → рассчитывается налог выбранного режима.
Налоги выключены → эффективный налог = 0 ₽.
```

Ставка налога не заменяется единицей. Она становится равной нулю.

## Фонд развития

```text
Галочка снята       → эффективный процент = 0%; сумма фонда = 0 ₽.
Галочка установлена → участвует выбранный процент.
```

## Резерв программы лояльности

```text
Галочка снята       → эффективный процент = 0%; резерв = 0 ₽.
Галочка установлена → участвует выбранный уровень 5%, 10% или 15%.
```

## Форс-мажоры

```text
Галочка снята       → резерв времени = 0 часов.
Галочка установлена → резерв рассчитывается по выбранному проценту.
```

## Исключение расходного блока

```text
Обратная галочка снята       → значения блока участвуют.
Обратная галочка установлена → все денежные/временные результаты блока = 0.
```

## Рабочее место

```text
Выбрано «Дома»  → домашняя ветка активна; офисная ветка даёт нулевой вклад.
Выбран «Офис»   → офисная ветка активна; домашняя ветка даёт нулевой вклад.
```

## Сайт

```text
Подрядчик → стоимость подрядчика участвует; собственные часы = 0.
Сам       → стоимость подрядчика = 0; участвуют собственные часы.
```

## Учёт

```text
Самостоятельно → время учёта участвует; стоимость бухгалтера = 0.
Специалист     → время самостоятельного учёта = 0; стоимость специалиста участвует.
```

# 7. Единая цепочка расчёта

```text
Сырое значение поля
→ проверка типа управляющего элемента
→ определение активной ветки
→ эффективное значение
→ групповой итог
→ общий итог модели
→ готовый результат calc()
→ отображение report.html
```

`report.html` не должен повторно смотреть на сырые галочки, режимы или значения полей. Он получает готовые эффективные результаты от `calc()`.

---

# 8. Почему нулевой вклад не вызывает деление на ноль

Расходные показатели складываются или вычитаются.

```text
Итоговые затраты = расход 1 + расход 2 + 0 + расход 4
```

Проблема деления на ноль возникает только у обязательных структурных величин, которые используются как делители. Поэтому:

- необязательные расходы обнуляются;
- обязательные делители валидируются;
- это две разные категории и две разные реакции интерфейса.

# 9. Финансовый результат текущего сценария

Для текущей ставки должен рассчитываться единый финансовый результат:

```text
Текущая выручка
− эффективные расходы дела
− эффективный налог
− эффективные банковские комиссии
− эффективный фонд развития
− эффективный резерв программы лояльности
− эффективная стоимость собственного сайта
=
финансовый результат
```

Финансовый результат может быть:

- положительным;
- равным нулю;
- отрицательным.

Отрицательный результат является корректным результатом модели, а не ошибкой ввода.

# 10. Доход и убыток

## 10.1. Положительный результат

Если финансовый результат больше или равен нулю, карточка показывает:

```text
Ваш текущий доход
53 071,92 ₽/мес
```

## 10.2. Отрицательный результат

Решение пользователя:

> Отрицательный результат должен быть обязательно показан со знаком минус. Скрывать его за нулём запрещено.

Предлагаемое поведение:

### Заголовок поля меняется

Было при положительном результате:

```text
Ваш текущий доход
```

Становится при отрицательном результате:

```text
Ваш убыток
```

### Значение показывается со знаком минус

```text
−30 228,83 ₽/мес
```

### Добавляется пояснение

```text
Дохода нет. При текущей ставке ваши расходы превышают выручку на 30 228,83 ₽ в месяц.
```

Таким образом, карточка не показывает одновременно «доход» и отрицательную сумму. Термин меняется в зависимости от знака результата.

---

# 11. Какие поля остаются в карточке при убытке

Карточка сохраняет три основных значения.

## Поле 1. Финансовый результат

### Если значение неотрицательное

```text
Ваш текущий доход
+53 071,92 ₽/мес
```

Плюс можно визуально не показывать, чтобы не перегружать интерфейс.

### Если значение отрицательное

```text
Ваш убыток
−30 228,83 ₽/мес
```

Минус показывается обязательно.

## Поле 2. Текущая стоимость часа

Остаётся введённой пользователем ценой:

```text
1 000 ₽/ч
```

## Поле 3. Текущая выручка в месяц

Остаётся положительной суммой полученных от клиентов денег:

```text
18 050 ₽/мес
```

Выручка и доход/убыток — разные величины. Выручка может быть положительной при отрицательном финансовом результате.

---

# 12. Как оформлять кольцо при убытке

Обычное кольцо «доход + расходы» не может корректно показать ситуацию, когда расходы больше выручки.

Предлагаемое правило:

## При положительном результате

Секторы:

- доход на руки;
- расходы и обязательные платежи;
- фонды и резервы, если включены.

Сумма секторов равна выручке.

## При отрицательном результате

Показываются:

- часть расходов, покрытая выручкой;
- непокрытый убыток.

Центральная подпись:

```text
Ваш убыток
−30 228,83 ₽/мес
```

Либо кольцо временно заменяется простой сравнительной плашкой:

```text
Выручка         18 050 ₽/мес
Затраты         48 279 ₽/мес
Убыток         −30 229 ₽/мес
```

Рекомендуемый вариант для первой тестовой версии — сравнительная плашка. Она проще и не создаёт ложной круговой пропорции.

# 13. Поля, которые нужно добавить в результат calc()

Предлагаемые канонические результаты текущего сценария:

```text
currentRevenueYear
currentRevenueMonth
currentTax
currentAcquiring
currentDevelopmentFund
currentLoyaltyReserve
currentSelfSiteCost
currentCostsTotal
currentFinancialResultYear
currentFinancialResultMonth
currentIsLoss
```

Дополнительно можно вывести:

```text
currentIncomeYear  = положительная часть результата;
currentLossYear    = отрицательная часть результата со знаком минус.
```

Однако предпочтительно хранить один истинный финансовый результат и определять подпись по его знаку.

Фактически внедрённые результаты текущего сценария:

```text
currentFund
currentDiscountReserve
currentSelfSiteCost
currentCostsTotal
currentResult
currentIncome
currentLoss
currentIsLoss
```

## 13.1. Результаты идеального сценария

Для карточки «Необходимый доход» внедрены:

```text
goalFund
goalDiscountReserve
goalSelfSiteCost
goalCostsTotal
goalResult
```

Единая формула:

```text
goalCostsTotal =
расходы дела
+ эффективный налог
+ эффективный эквайринг
+ goalFund
+ goalDiscountReserve
+ goalSelfSiteCost

goalResult = необходимая выручка − goalCostsTotal
```

В отключённой или неактивной ветке соответствующее `goal...`-поле остаётся в контракте со значением 0.

# 14. Что нужно изменить в report.html

1. Не рассчитывать текущий налог заново.
2. Не восстанавливать расходы по сырым полям.
3. Получать готовый финансовый результат из `calc()`.
4. Не применять `max(0, результат)`.
5. Если результат отрицательный, менять заголовок «Доход» на «Убыток».
6. Показывать отрицательную сумму со знаком минус.
7. Добавлять текст о превышении расходов над выручкой.
8. Менять состав визуального сравнения при убытке.

# 15. Правила форматирования

## Внутреннее значение

`calc()` сохраняет полную расчётную точность. Копейки и более длинная дробная часть не отбрасываются до завершения расчёта.

## Пользовательское денежное значение

Все денежные результаты показываются округлёнными до ближайшего целого рубля:

```text
53 071,92 ₽ → 53 072 ₽
50 800,63 ₽ → 50 801 ₽
2 814,44 ₽  → 2 814 ₽
```

Округлённое отображение не возвращается в формулы.

## Ноль

```text
0 ₽
```

Ноль не показывается как `−0 ₽`.

## Отрицательный результат

```text
−30 229 ₽
```

Используется настоящий знак минус `−`, а не дефис `-`.

Знак минус не скрывается цветом или подписью. Он является частью числа.

## Специальная практическая рекомендация

Если для конкретной ставки отдельно утверждено округление вверх до 100 ₽, оно применяется только в практическом блоке и не меняет точный расчёт.

# 16. Валидация и отрицательные значения

Важно различать:

## Отрицательный ввод

Например:

```text
Стоимость оборудования = −10 000 ₽
```

Это ошибка ввода. Анкета должна её запретить.

## Отрицательный результат

Например:

```text
Выручка − расходы = −30 000 ₽
```

Это допустимый и важный результат модели. Его нужно показать.

То есть правило «в полях только положительные значения» относится к пользовательскому вводу, но не к вычисленному финансовому результату.

---

# 17. Обязательные тесты

## Нулевой вклад

Для каждого отключаемого блока проверить:

- сырое значение сохраняется;
- эффективное значение становится нулём;
- групповой итог уменьшается ровно на этот показатель;
- отчёт получает ноль.

## Взаимоисключающие ветки

Проверить:

- дом / офис;
- подрядчик / собственный сайт;
- самостоятельный учёт / бухгалтер;
- все налоговые режимы.

## Убыток

Проверить текущие ставки:

```text
0 ₽/ч
1 000 ₽/ч
ставка чуть ниже безубыточности
точная ставка в ноль
ставка чуть выше безубыточности
текущая ставка по умолчанию
```

В каждом случае проверить:

- знак результата;
- заголовок «Доход» или «Убыток»;
- значение в месяц и год;
- пояснение;
- выручку;
- визуальное сравнение.

## Отрицательный ноль

Если после округления до целого рубля результат равен нулю, нужно показывать:

```text
0 ₽
```

а не:

```text
−0 ₽
```

# 18. Понятия, которые нужно закрепить в глоссарии

## Сырое значение

Значение, хранящееся в поле анкеты до применения условий участия в расчёте.

## Эффективное значение

Значение параметра после применения галочек, исключений и выбранной ветки; именно оно используется в формулах.

## Прямая галочка

Галочка, которая включает параметр: снята — вклад нулевой; установлена — используется сохранённое значение.

## Обратная галочка

Галочка исключения: снята — блок участвует; установлена — эффективные результаты блока равны нулю.

## Переключатель ветки

Элемент выбора одной активной ветки; вклады остальных веток равны нулю.

## Финансовый результат

Разница между выручкой и всеми эффективными затратами модели. Может быть положительной, нулевой или отрицательной.

## Доход

Положительный финансовый результат, остающийся после всех предусмотренных вычетов.

## Убыток

Отрицательный финансовый результат, возникающий, когда выручка меньше всех предусмотренных затрат. Показывается со знаком минус.

---

# 19. Принятые решения

1. Отключённый параметр не удаляется из структуры, а даёт нулевой вклад.
2. Неактивная ветка даёт нулевой вклад.
3. Обязательный делитель не обнуляется — расчёт останавливается до исправления.
4. Отчёт использует эффективные результаты `calc()`.
5. Отрицательный финансовый результат не скрывается.
6. Отрицательная сумма обязательно показывается со знаком минус.
7. При отрицательном результате подпись поля меняется с «Ваш текущий доход» на «Ваш убыток».
8. Добавляется пояснение: дохода нет, расходы превышают выручку на указанную сумму.

---

# 20. Принятое визуальное решение

Для первой тестовой версии утверждены:

1. динамический заголовок «Ваш текущий доход» / «Ваш убыток»;
2. настоящий знак минус у отрицательного результата;
3. сравнительная плашка «Выручка / Затраты / Убыток» вместо кольца при убытке;
4. пояснение о сумме превышения затрат над выручкой.

Точный отрицательный результат хранится в `calc()` и не обрезается до нуля.
