## Зачем

Перед тестовой публикацией нужно пройти каждое вводимое поле анкеты и закрепить допустимый диапазон, шаг и сообщения об ошибках. Денежные значения пользователь решила вводить без копеек, круглыми суммами с шагом до 100 ₽; для времени, процентов и коэффициентов правила определяются отдельно.

## Что сделать

- [ ] Составить полный список вводимых и выбираемых полей по блокам
- [ ] Разделить обязательные положительные и допустимые нулевые значения
- [ ] Для денежных полей установить ввод без копеек и согласованный шаг 100 ₽
- [ ] Для часов и коэффициентов утвердить допустимые дробные шаги
- [ ] Для процентов, сроков, площадей и количеств установить минимум и максимум
- [ ] Добавить межполевые проверки: рабочая площадь не больше общей и другие зависимости
- [ ] Показывать понятные ошибки без скрытой подмены введённых значений
- [ ] Добавить тесты минимальных, максимальных и недопустимых значений
- [x] Отдельно утвердить правила округления результатов отчёта

## Решения и правки

- 21.08.2026 — задача заведена.
- 21.08.2026 — Решение пользователя зафиксировано: денежные поля должны вводиться без копеек, реалистичными круглыми суммами; ориентир шага — 100 ₽. Общее правило «только положительные» не применяется вслепую: для каждого поля отдельно определяем, допустим ли ноль. Максимумы и правила дробности для часов, процентов и коэффициентов будут утверждаться при последовательном разборе calc.html.
- 22.08.2026 — Архитектурное правило пользователя: любой отключённый блок или неактивная опция остаётся в структуре модели, но её эффективное значение равно нулю. Формулы не должны удалять параметр или переходить на отдельную математику — они складывают единый набор эффективных значений. Для radio/select активна одна ветка, значения неактивных веток дают нулевой вклад. Обязательные знаменатели не обнуляются, а валидируются до расчёта.
- 22.08.2026 — К понятийному справочнику нужно добавить тип `exclude_checkbox` («Обратная галочка»): снята — блок участвует; установлена — все эффективные результаты блока равны нулю. Также закрепить различие отрицательного ввода (ошибка) и отрицательного результата (допустимый убыток).
- 22.08.2026 — Утверждено правило результатов отчёта: `calc()` хранит полную точность, все пользовательские денежные значения показываются округлёнными до ближайшего целого рубля. Специальное округление вверх до 100 ₽ остаётся только у отдельно утверждённых практических ставок. Правила вводимых денежных полей и их шаг 100 ₽ проходят отдельно по каждому полю.
