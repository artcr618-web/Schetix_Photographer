## Зачем

Сейчас разрезы и производные показатели считает скрипт прототипа, а не калькулятор. Источник правды должен быть один: если показателя нет в calc(), его нельзя выводить.

## Что сделать

- [x] Разрезы /мес, /нед, /день, /проект, /час съёмки определены как представление готовых годовых результатов
- [x] Себестоимость часа съёмки и наценка к себестоимости
- [ ] Запас прочности и съёмок до выхода в ноль
- [x] Износ камеры, стоимость срабатывания, выработка ресурса
- [ ] Окупаемость камеры по денежному потоку
- [x] Календарь года: 365 / 104 / 14
- [x] Исправить количество проектов в loadCur / loadGoal / loadZero при длительности съёмки больше 1 часа
- [ ] Завершить зеркало всех новых формул в проверить.py

## Решения и правки

- 18.08.2026 — задача заведена.
- 18.08.2026 — Первая часть перенесена в calc(): календарь (calDays, weekend, holidays, WD, VAC, SICK, ND, EFF), затвор и износ камеры (shutterPerHour, shutterLife, shotsYear, camName, camPrice, camLife, camAmort, camWear), себестоимость часа (costHour) и наценка (markup). Генератор прототипа больше не считает их сам, а берёт из расчёта. Осталось: разрезы /мес, /нед, /проект и показатели загрузки.
- 18.08.2026 — Перенесена вторая часть: загрузка под желаемый доход при любой цене часа — функция загрузка(ставка) в calc(), наружу идут loadCur, loadGoal, loadZero (съёмок, часов, дней, свободных дней, длина рабочего дня, съёмок в день), а также rateHour и rateZero. Прототип детализации больше не решает уравнение выручки сам. Осталось только деление на периоды (÷12, ÷43,8, ÷проекты, ÷часы) — это не отдельные показатели, а разрезы, их считает оболочка.
- 21.08.2026 — При проверке блока 05 подтверждена ошибка loadCur/loadGoal/loadZero: при длительности съёмки больше одного часа съёмочные часы используются как количество проектов. Три суммы карточек считаются отдельно и не повреждены, но строки требуемой загрузки нужно исправить до публикации.
- 22.08.2026 — Ошибка загрузки исправлена. Сначала рассчитываются съёмочные часы как `целевая выручка / ставка часа`, затем количество проектов как `съёмочные часы / длительность съёмки`. Для S=2 необходимый сценарий теперь показывает 120,33 проекта при 240,67 съёмочного часа, а не 240,67 проекта. Добавлены 4 постоянные проверки для S=0,5–8; общий результат 107 прошло, 0 упало.
- 22.08.2026 — Аудит показателя «Запас прочности»: в проекте это название используется в двух смыслах — как фонд развития/резерв скидки в анкете и как процент снижения выручки до точки безубыточности. Старая невнедрённая формула сравнивала необходимую выручку с выручкой в ноль (`1−Rb/R = 70,2%`), тогда как запас относительно текущей выручки равен `1−Rb/Rc = 53,1%`. Съёмок до выхода в ноль: 101,6 (практически 102) по текущей ставке и 64,6 (практически 65) по необходимой. Требуется решение по смыслу, названию и округлению перед внесением в calc().
