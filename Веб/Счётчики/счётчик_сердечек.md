# Настоящий счётчик сердечек для Tilda

Коротко: **на самой Tilda хранить число нельзя** — у неё нет базы данных для
произвольных значений. Но Tilda спокойно выполняет наш JavaScript, а число
живёт на бесплатном микро-сервере. Пользователю разницы никакой.

---

## Как это устроено сейчас

Важное уточнение: счётчик **уже не браузерный**. Число хранится на сервере
Abacus, а в браузере лежит только отметка «этот человек уже нажимал», чтобы
один посетитель не накрутил сотню.

| Что | Где хранится |
|---|---|
| Общее число сердечек | сервер счётчика (общее для всех) |
| Отметка «я уже нажимал» | localStorage браузера |
| Точка отсчёта (1780) | константа в коде |

Слабых мест два:

1. **Точку отсчёта видно в коде.** Любой откроет исходник и увидит `1780`.
2. **Abacus не умеет задавать значение** — только увеличивать. Поэтому
   стартовое число и приходится держать отдельным слагаемым.

Оба лечатся своим микро-сервером: там счётчику один раз задаётся стартовое
значение, и клиент получает уже готовое число.

---

## Вариант 1. Cloudflare Worker + KV (рекомендую)

Бесплатно: 100 000 запросов в день. Своя защита, свой домен, значение можно
задать один раз и забыть.

### Что сделать

1. Регистрация на `dash.cloudflare.com` (карта не нужна).
2. **Workers & Pages → Create → Worker**, имя `schetix-hearts`.
3. **Storage → KV → Create namespace**, имя `HEARTS`.
4. В настройках воркера: **Settings → Variables → KV Namespace Bindings**,
   переменная `HEARTS` → пространство `HEARTS`.
5. Вставить код из файла `счётчик_сердечек.js`, нажать **Deploy**.
6. Один раз задать стартовое число, открыв в браузере:
   `https://schetix-hearts.ВАШ.workers.dev/set?value=1780&key=СЕКРЕТ`
7. В коде окна заменить адрес счётчика на свой:
   ```js
   var СЧБАЗА  = 0;                                  // база теперь на сервере
   var СЧАДРЕС = 'https://schetix-hearts.ВАШ.workers.dev';
   ```

### Что умеет воркер

| Запрос | Действие |
|---|---|
| `GET /get` | вернуть текущее число |
| `GET /hit` | +1 и вернуть новое (не чаще раза в сутки с одного IP) |
| `GET /set?value=N&key=СЕКРЕТ` | задать значение (только вы) |

## Вариант 2. Google Apps Script + таблица

Дольше отвечает (0,5–2 с), но данные лежат в вашей Google-таблице, и их
видно глазами.

1. `script.google.com` → новый проект.
2. Код: чтение и запись ячейки `A1` таблицы, ответ в JSON.
3. **Deploy → New deployment → Web app**, доступ «Anyone».
4. Полученный адрес подставить в `СЧАДРЕС`.

Минус: у Apps Script нет CORS-заголовков в привычном виде, ответ приходится
забирать через JSONP или `no-cors`, код становится грязнее.

---

## Вариант 3. Оставить Abacus

Ничего не делать. Число уже общее и настоящее, растёт от реальных нажатий.
Минусы: чужой бесплатный сервис (закроется — счётчик замрёт), точка отсчёта
видна в коде, накрутка возможна любым, кто знает адрес.

Годится как временное решение на первые месяцы.

---

## Куда это вставляется на Tilda

Счётчик — часть скрипта окна благодарности, отдельно вставлять ничего не надо.
Само окно попадает на страницу одним из двух способов:

* **Блок T123 (HTML)** — лимит 100 000 байт на блок. Окно вместе со стилями
  и скриптом занимает около 12 КБ, помещается свободно.
* **Настройки страницы → Дополнительно → HTML-код внутри BODY** — если окно
  должно быть на всех страницах.

Ограничение Tilda про «нельзя загружать свои файлы» здесь не мешает: мы не
грузим файлы, а вставляем текст кода.

---

## Защита от накрутки

В воркере уже есть:

* один IP — одно сердечко в сутки (ключ `ip:<хеш>` в KV с временем жизни);
* метод `set` закрыт секретным ключом;
* CORS ограничен вашим доменом — с чужих сайтов дёргать не получится.

Полностью накрутку это не исключает (VPN, мобильная сеть), но делает её
бессмысленно трудоёмкой.
