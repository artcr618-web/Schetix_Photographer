## Принцип, от которого не отступаем

**Источник правды один — функция `calc()` в `web/calc.html`.**
Она считает всё. Дальше эти же числа упаковываются в три оболочки:

| Оболочка | Что это | Для кого |
|---|---|---|
| Красивый отчёт | `report.html`, картинки, диаграммы, объяснения | обычный человек |
| Подробная детализация | сухие таблицы, ничего не украшаем | тот, кто хочет проверить |
| Книга | `Калькулятор_ставки_часа.xlsx` | сверка модели, самопроверки |

Ни одна оболочка не считает сама. Если показателя нет в `calc()` —
сначала добавляем его туда, потом выводим.

**Проверка после любой правки:** `python3 ДОКУМЕНТАЦИЯ/4_инструменты/проверить.py schetix`
Сейчас: **61 прошло · 0 упало.** «Упало» быть не должно никогда.

## Задачи

Список задач живёт не здесь, а в **`ЗАДАЧИ/РЕЕСТР.md`** — он собирается
автоматически из документов задач, поэтому разойтись не может.

```
python3 ДОКУМЕНТАЦИЯ/4_инструменты/задачи.py список      что открыто
python3 ДОКУМЕНТАЦИЯ/4_инструменты/задачи.py новая "Название" P0
python3 ДОКУМЕНТАЦИЯ/4_инструменты/задачи.py запись З-003 "что решили"
python3 ДОКУМЕНТАЦИЯ/4_инструменты/задачи.py статус З-003 работе
python3 ДОКУМЕНТАЦИЯ/4_инструменты/задачи.py готово З-003
```

**Как это устроено.** У каждой задачи свой документ `ЗАДАЧИ/З-00N_имя.md`:
зачем она нужна, что сделать (чек-лист), связанные файлы и датированные
записи о принятых решениях. Закрыли — документ уезжает в `ЗАДАЧИ/_архив/`,
оттуда его всегда можно достать. Реестр показывает всё одной таблицей
с приоритетами и датой последнего изменения.

**Правила.** Новая задача — сразу свой документ, а не строка в чате.
Изменилось решение — дописываем запись с датой, старое не стираем:
последняя запись и есть действующая. Задача не закрывается, пока по ней
не отмечены все шаги.

## Правила работы

**Ничего не переименовывать и не менять по своей инициативе.**
Согласованная формулировка, порядок строк, состав таблицы — не трогаются,
пока не попросили. Если кажется, что можно лучше — сначала предложить
и дождаться подтверждения, потом делать. Каждая самовольная правка стоит
двух ходов: сначала переделать, потом вернуть обратно.

Это правило нарушалось: заголовок «Чтобы получить доход при выбранной
ставке» был согласован, а потом переписан без спроса; плашка «показан
расчёт по умолчанию» добавлена без спроса; подсказка «Распечатать»
сделана системным `title` вместо утверждённого стиля.

**Названия — только из справочника.**
Любое наименование, которое видит человек — заголовок раздела, название группы
на диаграмме, строка таблицы, подпись показателя — берётся из справочника
(`web/части/таблицы_прототип.py`, словарь `СПРАВОЧНИК`) буква в букву.
Нужного понятия нет — сначала заводим запись в справочнике (определение пишет
пользователь), потом используем название. Придумывать на ходу «Остальная
команда», «Реклама и продвижение», «Налоги и взносы» нельзя: разные названия
одного и того же приводят к разным группировкам, а разные группировки —
к ошибкам в расчётах и хаосу в отчёте.
Справочник — единственный источник. Глоссарий книги (`01_Глоссарий`,
`09i_Справочник`) приводится к нему, а не наоборот.
Сверка: `python3 ДОКУМЕНТАЦИЯ/4_инструменты/сверить_глоссарий.py schetix`.

**Один источник правды — таблица.**
Данные глоссария живут только в таблице: лист `01_Глоссарий` книги.
`модель/глоссарий.html` — та же таблица, собранная для чтения глазами.
Все скрипты берут данные из таблицы, ни из чего другого.

Порядок действий при любой правке:
1. Правим **таблицу** — лист `01_Глоссарий`.
2. Перестраиваем глоссарий: `python3 модель/глоссарий.py`
   (в книгу он при этом не пишет; запись — только по команде
   `python3 модель/глоссарий.py --в-таблицу`).
3. Перестраиваем служебные скрипты, чтобы правка дошла до калькулятора:
   `python3 web/части/справочник_в_отчёт.py` · `подсказки.py` · `демо.py`.
4. Проверяем: `python3 ДОКУМЕНТАЦИЯ/4_инструменты/проверить.py schetix` — «упало» 0.

Все разделы таблицы одного вида, одинаковые столбцы:
№ · Наименование · ID · Тип · Определение · Определение утверждено ·
Описание алгоритма · Формула (пример расчёта) · Где используется ·
Решение _(временный)_ · Справочник для сверки _(временный)_.
Служебные понятия, типы полей, блоки отчёта, понятия справочника —
такие же таблицы, без особого оформления. Временные столбцы удаляются,
когда всё согласовано.

**Этапы приведения глоссария в порядок.**
1. Сейчас: правим таблицу. Временные столбцы «Решение», «Справочник для сверки»
   и «Статус» — рабочие: через них сводим данные, занесённые раньше вразнобой.
2. Когда всё согласовано: временные столбцы **удаляем**.
3. После этого справочник сайта перестаёт хранить определения у себя и
   берёт их **из таблицы** — связь прописывается в `web/части/таблицы_прототип.py`.
   С этого момента источник один на весь проект: лист `01_Глоссарий`.

**Отчёт живёт и в книге.** Лист `06b_Отчёт_полный` — тот же отчёт, что видит
человек: показатель, живая формула Excel, единица, описание алгоритма словами,
значение из калькулятора и столбец «Сходится». Собирается
`python3 модель/отчёт_в_книгу.py`, значения — `пересчитать_книгу.py`
(нужен `pip install formulas`).

## Правила ведения карты

- Новая задача — сразу свой документ через `задачи.py новая`. Не в голову, не в чат.
- Решение принято или изменено — `задачи.py запись` с датой. Старое не стираем.
- Закрыли — `задачи.py готово`, документ уезжает в архив.
- Каждый разговор начинаем со сверки: `задачи.py список`.
