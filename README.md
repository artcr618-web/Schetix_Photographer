# Счётикс — юнит-экономика для фотографов

Счётикс рассчитывает стоимость часа фотосъёмки: выручку, расходы, налоги, резервы и требуемую ставку. Расчёт выполняется в браузере, бэкенд для него не нужен.

## Рабочая карта

Текущий порядок и принятые границы работы находятся здесь:

```text
Документация/Рабочее/ДОРОЖНАЯ_КАРТА.md
```

Эта карта имеет приоритет над старыми дорожными картами, историческими снимками, архивными задачами и старым описанием процессов.

## Действующий веб-контур

```text
Веб/index.html → Веб/calc.html → phc_report / ?data= → Веб/report.html
                                                   └──→ Веб/price.html
```

| Файл | Роль |
|---|---|
| `Веб/index.html` | Стартовая страница и вход в анкету. |
| `Веб/calc.html` | Анкета и единственная исполняемая финансовая функция `calc()`. |
| `Веб/report.html` | Отчёт, детализация, справочник и печатные режимы. |
| `Веб/price.html` | Самостоятельный редактируемый прайс. |
| `Веб/Tools/printPage.js` | Активный модуль предпросмотра и печати прайса. |

`calc()` формирует готовый объект `d`. Отчёт и прайс используют этот объект и не должны заново реализовывать финансовые формулы. Его действующий состав, типы, единицы и потребители зафиксированы в [`Документация/КОНТРАКТ_D.md`](Документация/КОНТРАКТ_D.md) и проверяются `Инструменты/проверить_контракт_d.py`.

### Канонический стартовый расчёт

«По умолчанию» — это не произвольный вызов формулы. Это первый запуск `calc.html`
в новом браузерном контексте с пустым `localStorage`: применяются стартовые
`data-exc`, автоматическая рекомендация фонда и автоматический подбор
допустимого налогового режима. Его полный golden snapshot хранится в
`Инструменты/эталоны/browser_default_calc.json`; проверка —
`node Инструменты/проверить_calc_browser_default.js . --assert`.

`Инструменты/харнесс.js {}` повторяет этот стартовый сценарий. Переопределения
харнесса остаются synthetic-сценариями для формул. При намеренном изменении
стартового состояния сначала проверяют новый JSON, затем **явно** обновляют
снимок командой `node Инструменты/проверить_calc_browser_default.js . --write-snapshot`;
обычная проверка snapshot сама не перезаписывает. Технический `DEMO` текущих
`report.html` и `price.html` пересобирает `python3 Инструменты/демо.py` из
browser-default; он нужен только development-копии.

Публикационный кандидат — `Веб/Публикация/report.html`. Он пересобирается командой
`python3 Инструменты/собрать_публикационный_отчёт.py`, не содержит исполняемого
`DEMO` и принимает только настоящий `d` через `?data=` либо `phc_report`.
Для выгрузки файл публикуется под именем `report.html` рядом с `calc.html`;
напрямую без результата он показывает только переход к анкете.

## Зафиксированные границы

- `Веб/Части/каркас.html` и другие файлы `Веб/Части/` оставлены в репозитории, но больше не являются зеркалом отчёта и не входят в обязательные проверки.
- `Книга/Калькулятор_ставки_часа.xlsx` — главный документ для итогового сведения. До отдельного согласования книга находится **только в режиме чтения**: её не перезаписывают и не пересобирают генераторами.
- `Архив/` не является рабочим источником. Он не используется для требований, тестов или активных ссылок.
- `PDF/` содержит исторические демонстрационные файлы. Они будут пересозданы только на финальной печатной фазе.

## Текущее состояние проверки

`python3 Инструменты/проверить.py /путь/к/проекту` запускает только активный
зелёный гейт: страницы, browser-default, DEMO, харнесс и headless-отчёт.
Исторический аудит (`--legacy`) и скрипты синхронизации книги удалены 28.09.2026;
сведение книги и печати остаётся отдельной согласуемой фазой.

## Ближайший порядок

1. Отделить активные проверки от каркаса, архива и книги.
2. Зафиксировать и поддерживать контракт `d` у анкеты, отчёта и прайса.
3. Починить локальные переходы и убрать рабочие ссылки на отсутствующий архив.
4. Согласовать и выполнить сведение основной книги.
5. Папка `Веб/Публикация/` подготовлена для будущей выгрузки; до полного аудита не считать её финальным чистовым комплектом. Кандидат `report.html` в ней сохраняет исходное имя файла и пересобирается отдельной командой.

## Локальная копия

Рабочая папка создана как неглубокий Git-клон `main`, чтобы не хранить локально всю историю репозитория:

```bash
git clone --depth 1 --single-branch --branch main --no-tags \
  https://github.com/artcr618-web/Schetix_Photographer.git \
  /home/user/Schetix_Photographer
```

Обычные `git pull` и новые коммиты доступны. Команда `git fetch --unshallow` загрузит полную историю и заметно увеличит размер рабочей папки.
