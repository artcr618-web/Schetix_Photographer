# ЧАСТЬ II. АЛГОРИТМ КАЖДОЙ ЗАДАЧИ

## 4. Три режима обращения

**А — точная команда.**  
«В блоке 03 замените „стоимость часа“ на „ставка часа съёмки“.»  
Не спрашиваю по мелочам. Ищу источник и зеркала, меняю минимум, проверяю, отчитываюсь.

**Б — неоднозначная команда.**  
«Исправьте „Всего расходов“.»  
Сначала показываю все места и числа, варианты, жду выбор. Пока нет «да» — файлы не трогаю.

**В — идея.**  
«Может, прибыль отдельной строкой?»  
Не меняю код. Разбираю влияние, предлагаю. После подтверждения заводим задачу.

   - название человеку → `СПРАВОЧНИК` в `web/части/таблицы_прототип.py`;
   - определение в книге → лист `01_Глоссарий`;
   - поле анкеты → DOM-id + лист `15_Реестр_полей`;
   - правило → лист `16_Реестр_правил`;
   - вид отчёта → `report.html` **и** `части/каркас.html`.
3. **Цепочка влияния.** Понятие → поле → `calc()` → поле `d` → блок отчёта → книга / DEMO / тесты. Архив не синхронизирую, пока не попросите.
4. **Стоп, если нужен смысл.** Безубыточность и фонды, два «всего расходов», 1752 vs 1533, переименование, дизайн.
5. **Снимок.** Что было в числах и в `git`, чтобы не спутать старый дефект с новым.
6. **Минимум.** Без попутной уборки и «улучшений».
7. **Зеркала.**
   - формула: `calc()` → отчёт не считает заново → `демо.py` → `06b` при нужде → `проверить.py`;
   - текст: справочник → генераторы → анкета/отчёт/каркас;
   - отчёт: оба HTML сразу.
8. **Проверка.** Всегда:

   ```bash
   python3 ДОКУМЕНТАЦИЯ/4_инструменты/проверить.py /home/user/schetix
   ```

   Сейчас норма: **114 прошло · 0 упало · 1 замечание**.  
   Плюс харнесс / jsdom / пороги экрана — по типу правки.

9. **Diff.** Нет лишних файлов, нет архива, нет сломанных диаграмм книги (`openpyxl` без zip их убивает).
10. **Отчёт вам.** Что изменено; в каких файлах; что сознательно не тронуто; проверки; что осталось; следующий логичный шаг.

## 6. Правила, которые нельзя нарушать

1. Ничего не переименовывать и не менять состав таблиц без «да».
2. Названия человеку — только из справочника. Нет понятия — сначала запись, определение пишете вы.
3. Текстовых пояснений на страницы не добавлять — только справочник и подсказки.
4. Дизайн — в З-029, не по ходу. Если вы сами сбиваетесь на вид — напоминаю.
5. Не улучшать соседнее. Увидел — сказал отдельно.
6. Книгу писать только zip-скриптами.
7. Новая существенная задача — документ `ЗАДАЧИ/З-0NN_*.md` и запись с датой. Старое не стираем.
8. Новые обзорные тома сам не пложу, пока вы не попросите.
