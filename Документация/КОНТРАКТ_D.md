# Контракт `d` — данные между анкетой, отчётом и прайсом

Обновлено: 27.09.2026 · формат контракта: `1`.

## Назначение

`d` — публичный результат `calc()` в `Веб/calc.html`. Он передаётся без
пересчёта финансовой модели:

```text
calc.html → d → localStorage[phc_report] / ?data= → report.html и price.html
```

Полный машиночитаемый источник — [`Инструменты/контракт_d.json`](../Инструменты/контракт_d.json).
Он фиксирует ровно **113 обязательных верхнеуровневых полей**; golden snapshot
`Инструменты/эталоны/browser_default_calc.json` хранит фактический чистый старт.

## Правила границы

- Все перечисленные поля обязательны в новом результате calc().
- Числа передаются без пользовательского форматирования; округление — задача представления.
- answers и catalog содержат только активные эффективные ветки анкеты.
- Потребитель не читает неизвестное поле `d`: каждое чтение должно быть объявлено в контракте.
- Изменение состава, типа или смысла поля требует изменения этого контракта, golden snapshot и проверок.

Техническая метка `_ts` добавляется только в `saveReport()` при сохранении
и **не является** полем результата `d`.

## Структурированные поля

### `answers`

Активные одиночные ответы для таблицы «Вводные данные». Каждый элемент:

```js
{ b: number, n: string, v: number|string, u: string }
```

`b` — номер блока, `n` — название, `v` — эффективное значение, `u` — единица. Неактивная ветка отсутствует.

### `catalog`

Активные позиции динамических каталогов:

```js
{ b: number, n: string, price: number, term: number, kind: string }
```

Исключённый каталог не передаёт элементы.

### `loadGoal`, `loadCur`, `loadZero`

Каждое поле — объект нагрузки либо `null`:

```js
{ shoots, hours, days, freeDays, dayHours, shootsPerDay } // все значения — number
```

## Значимые производные поля З-001

- `currentBreakEvenMargin` — **запас выручки до точки безубыточности** в текущем сценарии: `(Rc − Rb) / Rc`. Положительное значение означает запас, отрицательное — текущая ставка уже ниже точки безубыточности; при `Rc = 0` поле равно `null`. В детализации отчёта оно показывается с одним знаком после запятой без искусственного округления в безопасную или опасную сторону.
- `minShootsY` / `minShootsM` остаются точными значениями точки безубыточности в натуральном выражении по расчётной цене. При показе порог всегда округляется **вверх**: меньший целый объём не покрывает расходы. `zeroShootsY` / `zeroShootsM` — отдельный сценарий при ставке в ноль, а не дубль первого показателя.
- `profitY` — чистая прибыль для возврата вложений; `cushionY` — самостоятельный буфер ликвидности. Их сумма остаётся в прежнем поле `fundY`, поэтому расчёт и совместимость существующих результатов не меняются.
- `investment*` обслуживают витрину B024: это её три показанных направления и их сумма. `investmentPaybackYears = investmentTotal / profitY`; при нулевой чистой прибыли — `null`. Отдельной «окупаемости камеры» нет: одна сумма чистой прибыли не может одновременно окупить каждую покупку.
- `shootEquipmentWear` — износ всего съёмочного комплекта на одно срабатывание; отчёт больше не получает его делением годовой суммы самостоятельно.
- `directFrameCosts` — готовая годовая сумма прямых расходов B023: `depShoot + depOffice + depSoft + varSoft + depWs + varRent`. Включает технику, рабочий софт/подписки и рабочее место; исключает рекламу, банковские и бухгалтерские расходы, обучение и сайт. `report.html` получает только это готовое поле и не имеет fallback-формулы.

## Потребители

- `report.html` непосредственно читает **94** поля контракта: бюджет, время, детализацию, сценарии, налоги, вложения и печать.
- `price.html` непосредственно читает **9** полей: `NT`, `pool`, `rateWorkFull`, `S`, `sh`, `R`, `discP`, `K`, `cl`.
- Валидатор сверяет фактические обращения обоих HTML с метками `consumers` в JSON. Новое чтение неизвестного поля или устаревшая декларация останавливают active-гейт.

### Прямые расходы на готовый кадр

`directFrameCosts` — обязательный результат `calc()`, а не совместимый внешний вход. Финансовая формула находится только в калькуляторе; отчёт использует готовую годовую сумму исключительно для представления стоимости часа и кадра. Отсутствие этого поля в старом/внешнем payload не запускает скрытый пересчёт в `report.html`.

## Как менять контракт

1. Сначала согласовать пользовательский смысл и изменить `calc()`.
2. Запустить browser-default. Если изменение намеренное — осознанно обновить его golden snapshot.
3. Внести новое или изменённое поле в `Инструменты/контракт_d.json`: группа, тип, единица, потребители и при необходимости смысл.
4. Изменить отчёт/прайс только после описания поля в контракте.
5. Прогнать:

```bash
python3 Инструменты/проверить_контракт_d.py /путь/к/проекту
python3 Инструменты/проверить.py /путь/к/проекту
```

Проверка не читает книгу, архив, PDF или `Веб/Части/`: это контракт действующего веб-контура.
