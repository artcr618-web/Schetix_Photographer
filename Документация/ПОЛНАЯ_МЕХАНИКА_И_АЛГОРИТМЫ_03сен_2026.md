# ЧАСТЬ I · ЧТО ТАКОЕ СЧЁТИКС

Счётикс — калькулятор юнит-экономики съёмочного часа фотографа. Человек
заполняет анкету (20 вопросов), а Счётикс отвечает: какую ставку часа
установить, чтобы после покрытия всех расходов, налогов, страховых взносов,
банковских комиссий и заложенных резервов оставался ровно Желаемый доход.

Принципиальное устройство:

- **всё считается в браузере** — бэкенда нет, данные остаются у пользователя;
- **один исполняемый расчёт** — функция `calc()` в `Веб/calc.html`;
- **одна цепочка данных**:

```text
анкета (calc.html) → calc() → объект d (101 поле) → report.html → режим печати → PDF
                                   ↕ формульное зеркало
                    Книга/Калькулятор_ставки_часа.xlsx (лист calc)
```

Ни отчёт, ни PDF, ни книга не имеют права считать по-своему: report и PDF
получают готовые поля `d`, книга — совместимое зеркало, доказанное
15 сценариями сверки.

## 3. Динамические каталоги CAT

Объект `CAT` (строка ~2816) хранит стартовые позиции восьми каталогов.
Три вида расчёта позиции (`k`):

- **`life`** — амортизация: годовой вклад = цена / срок службы (лет).
  Каталоги Form001, Form002, Form004, Form013;
- **`per`** — регулярный платёж: годовой вклад = цена × число платежей в году
  (1/4/12). Каталоги Form003, Form007, Form010;
- **`months`** — обучение (Form006): в `sumF` даёт 0, считается отдельно
  (стоимость + упущенный доход, распределённые на `edu_life`).

Суммирует каталог `sumF(f)`: обходит строки таблицы `t_<Form>`, применяет вид
расчёта; исключённый каталог даёт 0. Первые две строки Form001 (камера и
объектив) — «несносимые»: крестик очищает поля, но строку не удаляет.
Первая строка Form001 считается камерой для блока «Износ камеры»
(временное решение до З-004).

## 4. Управляющие элементы и эффективные нули

Словарь `EXC{}` хранит состояния обратных галочек «Не учитывать этот блок»
(RULE-006): блок остаётся в структуре, его вклад — эффективный ноль, сырые
значения сохраняются. Прямые галочки (`fm_on`, `fund_on`, `disc_on`) включают
параметр (RULE-005). Radio/select выбирают ветку — неактивная ветка даёт ноль
(RULE-007). `tax_off` обнуляет налоги и взносы во всех сценариях, сохраняя
выбранный режим (RULE-017). `own_home` даёт эффективный ноль аренде жилья,
коммунальные продолжают считаться по доле метров (RULE-010).

```text
WD = 247 дн           рабочих дней (производственный календарь РФ 2026)
VAC = 20 дн           отпуск в рабочих днях (28 календарных, ст. 115 ТК)
SICK = 8 дн           больничный в рабочих днях (10 календарных, среднее)
EFF = 7 ч             эффективный рабочий час дня (8 − 1 на перерывы, ст. 91 ТК)
DW = 5                дней в неделе
ND = WD−VAC−SICK = 219 дн   рабочие дни после отпуска и больничного
NT = ND×EFF = 1 533 ч       эффективное рабочее время за год
NW = ND/DW = 43,8 нед
Календарь: 365 = 104 выходных + 14 праздничных + 247 рабочих
Лимиты 2026: НПД 2,4 млн ₽; УСН порог НДС 20 млн ₽; АУСН 60 млн ₽
```

## 6. Функция `calc()` — построчный алгоритм

### Шаг 1 · Время

```text
promo = promo_per_day × ND                    (0, если блок исключён)
accT  = acc_per_quarter × 4                   (только ветка «веду сам»)
idle  = ND × (8 − EFF) = 219 ч                неэффективное рабочее время
side  = promo + accT                          операционное время
ЗАЩИТА: side ≤ 0,8 × NT — не-съёмочное время не может съесть весь год;
        при превышении promo и accT масштабируются пропорционально
gross = NT − side
fmT   = fm_on ? gross × fm_pct/100 : 0        резерв времени
pool  = gross − fmT                           проектное время (1 083 ч по умолчанию)
```

### Шаг 2 · Проект

```text
S  = shoot_manual (длительность минимального заказа, ч)
K  = post_ratio, M = 1 + K
cl = client_time (0, если блок исключён)
pt = S×M + cl                продолжительность съёмочного проекта (5 ч по умолчанию)
py = pool / pt               проектов в год (216,6)
sh = py × S                  СЪЁМОЧНОЕ ВРЕМЯ — знаменатель ставки (216,6 ч)
post = sh × K                постпродакшн (649,8 ч)
clT  = py × cl               проектное клиентское время (216,6 ч)
```

### Шаг 3 · Финансовые расходы C

```text
Рабочее место (wsY):
  дом:   (аренда_или_0_при_own_home + коммунальные) × (cab_area/home_area) × 12
  офис:  (office_rent + office_util) × 12
  исключено: 0
Обучение (eduY): (Σ стоимость курсов + месяцы_без_дохода × income_month) / edu_life
Сайт (siteY): ветка «нанимал» → site_cost / site_life; «сам» → 0 деньгами,
  вместо денег поправка знаменателя sdiv = site_hours / (site_life × NT)
amort = sumF(Form001)+sumF(Form002)+sumF(Form004)+sumF(Form013)+eduY+siteY
        = Финансовые вложения (инвестиции)
vari  = sumF(Form003)+sumF(Form010)+sumF(Form007)+бухгалтер+wsY
        = Регулярные расходы специалиста
C = amort + vari = Финансовые расходы            (562 667,78 ₽/год по умолчанию)
```

### Шаг 4 · Цель и процентные доли

```text
Ny  = income_month × 12 = Желаемый доход за год  (1 322 592 ₽)
vacY = Ny / 12 — Резерв на отпуск: не новый расход, а месячная доля дохода,
       которую нельзя считать свободными деньгами
a = эквайринг + дополнительные комиссии, где
    эквайринг = acq_rate/100 × acq_share/100 (только если строка не удалена)
fundP = fund_on ? fund_pct/100 : 0
discP = disc_on ? disc_pct/100 : 0
ПРЕДЕЛЫ (иначе при 30+30+15 % знаменатель падал до 0,25 и выручка взлетала
к бессмысленным 9,4 млн): a ≤ 10 %, fundP ≤ 20 %, discP ≤ 15 %
D = 1 − a − sdiv − fundP − discP;  D ≥ 0,40 (отчисления не больше 60 %)
```

### Шаг 5 · Налоговое ядро — налог как честная функция выручки

Выбранный режим раскрывается: `npd` → npd4/npd5/npd6 по типу заказчиков
(4 % физлица, 6 % юрлица, 5 % смешанные — середина). `tax_off` → ставка 0.

```text
взносыОт(база) = FIX + min(max(0, база − THR) × 1 %, CAP)

taxOf(Rx):
  tax_off или Rx ≤ 0        → 0
  НПД (4/5/6 %)             → Rx × ставка (взносов нет)
  УСН «Доходы» 6 %          → max(0, Rx×6 % − взносы) + взносы
                              (взносы уменьшают налог, база взносов — выручка)
  АУСН «Доходы» 8 %         → Rx × 8 % (взносов нет)
  УСН «Доходы−расходы» 15 % → база = max(Rx×(1−a) − C − взносы, 0);
                              взносы зависят от базы, база — от взносов:
                              12 итераций подстановки; налог = max(база×15 %,
                              Rx×1 % минимальный) + взносы
  АУСН «Доходы−расходы» 20 %→ база = max(Rx×(1−a) − C, 0);
                              налог = max(база×20 %, Rx×3 %); взносов нет
```

### Шаг 6 · Выручка делением пополам

У налога есть изломы (минимальный налог, потолок допвзноса), поэтому
выручка ищется численно — 90 шагов бисекции на отрезке [0; 10⁹]:

```text
выручкаПод(цель, доля):
  ищем m: m × доля − C − taxOf(m) = цель

R_ = выручкаПод(Ny, D)          — Выручка целевого сценария (2 042 534,97 ₽);
                                  если sh = 0 — выручка 0, анкета не пускает в отчёт
Rb = выручкаПод(0, 1 − a − sdiv) — Точка безубыточности (609 607,56 ₽):
                                  БЕЗ добровольных фондов (решение владельца
                                  25.08: резервы — дополнительный расход)
```

### Шаг 7 · Итоги трёх сценариев

```text
Целевой (Желаемый доход):
  taxAll = taxOf(R_); aq = R_ × a
  totalExpenses = C + taxAll + aq = Всего расходов (719 942,97 ₽) — утверждённая
    группа: без резервного фонда и компенсации инвестиционного времени
  goalFund = R_×fundP; goalDiscountReserve = R_×discP; goalSelfSiteCost = R_×sdiv
  goalCostsTotal = C + aq + taxAll + goalFund + goalDiscountReserve + goalSelfSiteCost
  goalResult = R_ − goalCostsTotal  (= Ny с точностью бисекции)
  rateHour = R_ / sh = ЖЕЛАЕМАЯ СТАВКА (9 429,99 ₽/ч по умолчанию)

Текущий (по current_rate, те же эффективные параметры):
  Rc = cur × sh; taxC = taxOf(Rc); aqC = Rc × a
  currentCostsTotal = C + aqC + taxC + Rc×fundP + Rc×discP + Rc×sdiv
  currentResult = Rc − currentCostsTotal       (636 863,02 ₽; может быть < 0 —
    настоящий убыток, не обрезается: RULE-011/012)
  currentIncome = max(result, 0); currentLoss = min(result, 0); currentIsLoss

В ноль:
  rateZero = Rb / sh = Ставка в ноль (2 814,44 ₽/ч)
  zeroShootsY = Rb / (rateZero × S); zeroShootsM = /12 — съёмок для покрытия
    расходов при Ставке в ноль (показ округляется вверх)
  minShootsY = Rb / (R_/py) — то же покрытие по Желаемой ставке (64,65/год; 5,39/мес)
```

### Шаг 8 · Производные показатели

```text
Себестоимость часа съёмки: costHour = (C + taxB + aqB) / sh — налоги и
  эквайринг от СОБСТВЕННОЙ базы безубыточности, не от целевой выручки
  (иначе в себестоимость попадали платежи с желаемого дохода) = 2 814,44 ₽/ч
Наценка: markup = rateHour/costHour − 1 (235 %)
workHours = ND × 8 = 1 752 ч — Рабочее время «как у наёмного»
rateWork = (Ny × 11/12) / workHours = Доход в час на руки (692 ₽/ч)
rateWorkFull = R_ / NT = Базовая ставка (1 332,38 ₽/ч) — для услуг вне площадки
Износ камеры: камера = первая строка Form001; амортизация = цена/срок;
  shotsYear = shutter_per_hour × sh; camWear = амортизация/срабатывания
Загрузка(ставка): съёмочныхЧасов = R_/ставка; съёмок = часы/S;
  часов = съёмок×pt + side + fmT; дней = часов/EFF; свободных = 365 − дней —
  считается для rateHour, current_rate и rateZero (loadGoal/loadCur/loadZero)
```

### Шаг 9 · Сборка ответов анкеты

## 7. Автоподбор налогового режима и лимиты

- `подобрать()` (галочка `tax_auto`): перебирает npd/usn6/usn15/ausn8/ausn20,
  для каждого запускает `calc()` и сравнивает **требуемую выручку R** — на руки
  всегда выходит ровно желаемый доход, поэтому сравнивать «на руки»
  бессмысленно; выгоднее режим с меньшей необходимой выручкой. Режимы,
  не проходящие по лимиту, отбрасываются.
- `лимит()`: если выручка превысила лимит НПД — режим по закону слетает;
  анкета сама переставляет на УСН 6 % (проверено: даёт больше всех на руки
  выше лимита НПД), предупреждает полосой (12 секунд), прячет пункт НПД из
  списка, а когда цифры возвращаются в лимит — восстанавливает выбор.
