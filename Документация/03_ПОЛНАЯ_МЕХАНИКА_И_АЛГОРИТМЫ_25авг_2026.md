# ЧАСТЬ I. ПРОДУКТ И ПУТЬ ПОЛЬЗОВАТЕЛЯ

## I.1. Один вопрос продукта

Какую цену назначить за **час съёмки на площадке**, чтобы за год после всех расходов дела, налогов, взносов, эквайринга, фонда развития, запаса на скидку и доли собственного сайта на руках остался **желаемый доход**.

Клиент оплачивает только съёмочные часы. По умолчанию это 216,6 ч из 1 752 ч рабочего года (~12 %). Ставка должна оплатить весь остальной труд.

## I.2. Главное тождество

```
R × D − C − налог(R) = Ny
```

| Величина | Смысл | По умолчанию |
|---|---|---|
| `Ny` | желаемый доход за год = `income_month × 12` | **1 322 592 ₽** |
| `C` | расходы дела (амортизация + текущие), без налога и эквайринга | **562 667,78 ₽** |
| `D` | доля выручки после процентных изъятий: `1 − эквайринг − сайт_сам − фонд − скидка` | **0,973** |
| `R` | необходимая выручка (ищется численно) | **2 042 534,97 ₽** |
| Ставка | `R ÷ съёмочные часы` | **9 429,99 ₽** → показ 9 430 ₽; практическая обложка **9 500 ₽** (вверх до 100 ₽) |

Проверка на НПД 5 %: `2 042 534,97 − 562 667,78 − 102 126,75 − 55 148,44 = 1 322 592,00` — сходится до копейки.

## III.2. Не-съёмочное время и предохранитель

```
promo = promo_per_day × ND          // 2 ч/день × 219 = 438 ч (поиск заказов)
accT  = (учёт сам) ? acc_per_quarter × Q : 0    // 3 × 4 = 12 ч
side  = promo + accT                // 450 ч — операционное время
```

**Предохранитель 80 %:** не-съёмочная работа не может съесть весь год. Если `side > NT × 0,8`, обе величины пропорционально сжимаются до предела. Проверено вживую: при продвижении 7,5 ч/день side обрезается до 1 226,4 вместо 1 642,5, съёмочных часов остаётся 61,32, ставка вырастает до 33 309 ₽ — заниженно, но осмысленно (раньше уходило в минус).

```
gross = NT − side                   // 1 083 ч
fmT   = галочка fm_on ? gross × fm_pct : 0        // по умолчанию 0
pool  = gross − fmT                 // 1 083 ч — проектное время
```

## III.4. Расходы дела C

```
  = 0 при удалённой строке эквайринга (BANK_ACQ_ON=false)
потолки: a ≤ 10 % · фонд ≤ 20 % · скидка ≤ 15 %
фонд  = галочка fund_on ? fund_pct  : 0     // по умолчанию 0
скидка= галочка disc_on ? disc_pct  : 0     // по умолчанию 0
D = 1 − a − sdiv − фонд − скидка;  if (D < 0,40) D = 0,40   // отчисления ≤ 60 %
```

Доп. комиссии банка — динамические строки «название + %», считаются от всей выручки; эквайринг особый: применяется только к доле безналичных оплат и удаляется вместе с полем доли.

## III.6. Налог — честная функция выручки `taxOf(Rx)`

Режим: `regime` (select) → НПД раскрывается по заказчикам `npd_who` (phys 4 % / mix 5 % / jur 6 %). Галочка `tax_off` («без оформления») → ставка 0 (RULE-017: выбор режима сохраняется, вклад нулевой).

| Режим | Формула |
|---|---|
| НПД 4/5/6 | `Rx × ставка` |
| УСН 6 | `max(0, Rx×6 % − взносы) + взносы`, взносы = `FIX + min(max(0, Rx−THR)×1 %, CAP)` |
| АУСН 8 | `Rx × 8 %` |
| УСН 15 | база `б = max(Rx×(1−a) − C, 0)`; взносы считаются от базы итеративно (12 проходов, они сами уменьшают базу); налог `max(б×15 %, Rx×1 %) + взносы` |
| АУСН 20 | `max(б×20 %, Rx×3 %)`; у ИП-соло без работников страховых взносов нет |

История: раньше база УСН 15 / АУСН 20 бралась от желаемого дохода (`Ny/(1−ставка)`) и почти не зависела от выручки — точки безубыточности не сходились. Исправлено на расчёт от самой выручки.

## III.7. Выручка под цель — деление пополам

```
выручкаПод(цель): lo=0, hi=1e9; 90 итераций половинного деления
  пока m×D − C − taxOf(m) < цель → lo=m
```

Численно, потому что у налога изломы (минимальный налог, потолок взноса) — одной формулой не описать. Точность после 90 итераций — копейки.

```
R  = (sh>0) ? выручкаПод(Ny) : 0        // 2 042 534,97 ₽
taxAll = taxOf(R)                        // 102 126,75 ₽
aq     = R × a                           // 55 148,44 ₽
ставка = rateHour = R / sh               // 9 429,99 ₽
```

Если съёмочных часов не осталось (`sh = 0` — нулевая длительность или всё время съедено не-съёмочной работой) — выручка 0, анкета не пускает в отчёт (`проверитьПоля` + тост).

## III.8. Три сценария — одна формула, разные ставки

Каждый необязательный параметр остаётся в структуре, но при отключении его эффективное значение — ноль (RULE-004…007). Отчёт ничего не решает сам (RULE-001, 016).

**Идеальный (цель):**
```
goalFund = R × фонд;  goalDiscountReserve = R × скидка;  goalSelfSiteCost = R × sdiv
goalCostsTotal = C + aq + taxAll + фонды + сайт   // 719 942,97 ₽
goalResult = R − goalCostsTotal                   // = Ny = 1 322 592 ₽
```

**Текущий (по ставке пользователя `cur` = 6 000 ₽/ч):**
```
Rc = cur × sh                       // 1 299 600 ₽
taxC = taxOf(Rc)                    // 64 980 ₽
aqC  = Rc × a                       // 35 089,20 ₽
currentCostsTotal = C + aqC + taxC + фонды(cur) + сайт(cur)   // 662 736,98 ₽
currentResult = Rc − currentCostsTotal             // 636 863,02 ₽
currentIncome = max(результат, 0);  currentLoss = min(результат, 0)
currentIsLoss — флаг убытка (RULE-012: «Ваш убыток», настоящий минус, не обрезается)
leftC = currentResult (совместимое имя контракта)
```

**В ноль:**
```
Rb = выручкаПод(0)                  // 609 607,56 ₽
rateZero = Rb / sh                  // 2 814,44 ₽
```

## III.9. Производные ставки часа (названия согласованы)

| Показатель | Формула | По умолчанию | Смысл |
|---|---|---|---|
| Доход в час на руки (`rateWork`) | `(Ny × 11/12) ÷ (ND × 8)` | **692,00 ₽** | сколько специалист получает за час любой работы; отпускной месяц выключен (утверждено 25.08, паспорт в «Описаниях расчётов») |
| Базовая ставка (`rateWorkFull` / книга `base_rate`) | `R ÷ NT` | **1 332,38 ₽** | цена часа для клиента на услуги вне съёмочной площадки (паспорт — в «Описаниях расчётов») |
| Стоимость клиентского часа (`rateClient`) | `R ÷ pool` | **1 886,00 ₽** | услуги вне съёмки (консультации, организация): час вытесняет проектную работу |
| Себестоимость часа съёмки (`costHour`) | `(C + taxAll + aq) ÷ sh` | **3 323,84 ₽** | всё, что уходит, на один оплаченный час |
| Наценка (`markup`) | `rateHour / costHour − 1` | **183,7 %** | — |
| Резерв на отпуск (`vacY`) | `Ny / 12` | **110 216 ₽** | один месячный доход — не свободные деньги; с 25.08 отдельное поле контракта и сегмент кольца |

Формулы `rateWork` и `rateWorkFull` изменены последним коммитом 25.08 (см. Часть XII) — тома 01–02 и корневые документы содержат прежние числа (755 и 1 166).

## III.10. Загрузка при трёх ценах часа

```
загрузка(ставка):
  съёмочныхЧасов = R / ставка
  съёмок = съёмочныхЧасов / S            // делится на длительность, а не на часы

```

| В ноль | 2 814 ₽ | 725,7 | 4 078,7 | 582,7 | 18,6 ч (невозможно: свободных дней −218) |

## III.11. Износ камеры и затвор

```
shotsYear = 350 × 216,6 = 75 810         // срабатываний за год
```

# ЧАСТЬ V. ОТЧЁТ `report.html` — 21 БЛОК И ВСЁ, ЧТО В НИХ

## V.1. Данные и правила показа

`loadData()`: `?data=` (base64, обязательно `decodeURIComponent` — иначе `atob` падает и отчёт молча показывает демо) → `localStorage.phc_report` → DEMO (расчёт по умолчанию, показывается только по `?demo=1`; без данных отчёт предлагает заполнить анкету — правило публикационной копии, RULE-019).

## VII.2. Ключевые формулы листа 02 (для сверки с `calc()`)

- `net_days = work_days − vacation_work − sick_work` = 219; `net_time = net_days × eff_hours` = 1 533; `idle_time = net_days × (8−7)` = 219.
- `side_time = promo_time + accounting_time` = 450; `pool_gross = net_time − side_time` = 1 083; `project_pool = pool_gross − fm_time`.
- `project_time = shoot_duration × (1+post_ratio) + client_time` = 5; `projects_year = project_pool / project_time` = 216,6; `shooting_time = projects_year × shoot_duration` = 216,6.
- `total_costs = investment + variable_costs` = 562 667,78; `dep_*` и `var_*` — `SUMIF(cat_form, "FormXXX", cat_year)`.

- Налоги: `fixed_contrib 57 390`, `contrib_threshold 300 000`, `extra_contrib 1 %`, `contrib_cap 321 818`, `min_tax_usn 1 %`, `min_tax_ausn 3 %`, `acquiring = acq_rate × acq_share`, `limit_npd 2,4 млн`, `vat_threshold 20 млн`, `limit_ausn 60 млн`.

## VII.3. Чем книга отличается от `calc()`

1. Выручка в книге — **алгебраически** (например, НПД: `(Ny + C) / ((1 − acquiring − sdiv) − ставка)`), в коде — бисекцией. Для НПД и УСН 6 результаты совпадают до копейки; для УСН 15 / АУСН 20 книга решает то же уравнение упрощённо (взносы от `Ny/(1−ставка)`) — расхождение в пределах нескольких рублей, «на руки» сходится в обоих (проверка R24).
2. В книге **нет** параметров фонда развития, запаса на скидку, доп. банковских комиссий, автовыбора НПД по заказчикам (есть три раздельные ставки), износа камеры и затвора, загрузки, трёх сценариев в терминах `calc()` (текущий считается от `current_rate × shooting_time × (1 − ставка − эквайринг) − total_costs`). Отсюда 21 показатель без формул на `06b` (З-033).
3. `09f`, `09b` (строка 9.1), `09i`, `06_Отчёт` (доход по ролям) — устаревшие фрагменты (см. XII).
