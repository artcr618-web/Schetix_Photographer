# Аудит папки `Инструменты`

Проверено: 27.09.2026  
Статус: действующий технический документ

## Вывод

`Веб/calc.html` не вызывает ни один файл из `Инструменты/` в браузере посетителя. Значит, ни один из них не является production-зависимостью калькулятора. Папка нужна для воспроизводимой разработки: расчётных тестов, технического DEMO, договора `d`, ведения задач, публикационных проверок и будущей согласованной синхронизации книги.

В папке нет неиспользуемого исполняемого скрипта, который следует удалить сейчас. Два инструмента (`замерить_вёрстку.js`, `снять_preview.js`) запускаются вручную, а не из другого скрипта; они сохранены как полезные инструменты визуальной приёмки. Книга пока заморожена по решению владельца: инструменты её пересборки **не запускаются** при обычной веб-разработке, но сохраняются как единый, документированный контур будущей синхронизации.

Единственная лишняя зависимость найдена и удалена: прямой `puppeteer-core` из `package.json`. Его никто не импортирует напрямую; он остаётся транзитивной зависимостью `puppeteer` и поэтому доступен самому пакету, когда это нужно.

## 1. Обязательный зелёный контур веб-разработки

Эти файлы непосредственно участвуют в обычной команде:

```bash
python3 Инструменты/проверить.py "$PWD"
```

| Файл | Роль | Почему оставлен |
|---|---|---|
| `проверить.py` | Единая точка входа зелёного гейта; `--legacy` — изолированный исторический аудит. | Основная постоянная команда проверки. |
| `проверить_активный_контур.py` | Оркестратор browser-default, контракта, харнесса и headless-отчёта. | Защищает исполняемую цепочку `calc → report / price`. |
| `проверить_calc_browser_default.js` | Поднимает чистый JSDOM `calc.html`, сверяет golden snapshot и DEMO. | Единственный тест реального чистого жизненного цикла анкеты. |
| `проверить_контракт_d.py` | Проверяет состав, типы и потребителей публичного результата `d`. | Не даёт калькулятору, отчёту и прайсу разойтись молча. |
| `проверить_report_headless.js` | Проверяет рендер `report.html` в JSDOM по нескольким сценариям. | Ловит ошибки интерфейса и передачи данных, которые не видны харнессу. |
| `харнесс.js` | Выполняет фактические `calc()` и `parts()` без браузерной оболочки; принимает synthetic-переопределения. | Нужен инвариантам модели, отчёту, книго-сценариям и диагностике формул. |
| `контракт_d.json` | Машиночитаемый договор 113 полей `d`. | Источник состава контракта для постоянной проверки. |
| `эталоны/browser_default_calc.json` | Golden snapshot чистой анкеты. | Фиксирует согласованный browser-default и не позволяет случайно менять его. |
| `демо.py` | Пересобирает development DEMO в `report.html` и `price.html` из реального browser-default. | Поддерживает рабочий DEMO без ручного копирования цифр. |
| `собрать_публикационный_отчёт.py` | Собирает `Веб/Публикация/report.html` из development-отчёта, вырезая исполняемый DEMO и добавляя безопасное пустое состояние. | Единственный способ обновить публикационный артефакт без ручного расхождения копий. |
| `проверить_публикационный_отчёт.js` | Проверяет актуальность сборки, отсутствие DEMO, прямое пустое открытие и передачу `d` через localStorage и `?data=`. | Не допускает публикации development-значений. |
| `package.json`, `package-lock.json` | Версии JSDOM и Puppeteer для воспроизводимых проверок. | `npm ci --ignore-scripts` восстанавливает среду после чистого старта. |

### Зависимости Node.js

| Пакет | Реальный потребитель |
|---|---|
| `jsdom` | browser-default, headless-отчёт, static-preview и проверки публикационного отчёта. |
| `puppeteer` | ручные замеры вёрстки в настоящем Chromium. |
| `puppeteer-core` | прямой dependency удалён: исходники его не импортируют, а `puppeteer` поставляет его транзитивно. |

`Инструменты/node_modules/` — не часть репозитория и не постоянный артефакт. Обычная проверка при отсутствии модулей сама выполняет `npm ci`; после финальной сдачи временная папка удаляется.

### Проверка уязвимостей npm

На дату аудита `npm audit` показывает **4 high** в цепочке *только dev-зависимости* Puppeteer: `puppeteer` → `puppeteer-core` / `@puppeteer/browsers` → `extract-zip`. Эти пакеты не поставляются посетителю и не участвуют в выполнении `calc.html` в браузере. Автоматическое предложение npm ведёт к принудительной смене версии Puppeteer и потому не применялось без отдельной проверки визуального инструмента `замерить_вёрстку.js`. Это не блокирует действующий зелёный веб-гейт, но является отдельной задачей планового обновления dev-зависимости.

## 2. Постоянные ручные средства разработки

| Файл | Когда запускать | Статус |
|---|---|---|
| `задачи.py` | Новая задача, запись решения, закрытие и пересборка реестра. | Обязателен для порядка в `Задачи/`. |
| `замерить_вёрстку.js` | После заметного CSS/UI-изменения: размеры, допуски, скриншоты, сравнение с сохранённой базой. | Нет программного вызывающего кода; это намеренный ручной инструмент визуальной регрессии. |
| `снять_preview.js` | После обновления development DEMO или разметки отчёта: пересобрать `Веб/preview.html`. | Намеренный генератор статического примера отчёта без `<script>` и без формул; на этот файл ведут три карточки анкеты. |
| `сверить_глоссарий.py` | Перед публикацией терминологии или согласованной правкой книги. | Проверяет книгу, пользовательский справочник и лист «Состав». |
| `значения_по_умолчанию.py` | При пересборке зеркала книги либо аудите CAT/default-значений. | Извлекает фактические значения из `calc.html`; используется миграцией каталога и legacy-аудитом. |

## 3. Замороженный контур синхронизации основной книги

Эти файлы **нужны**, но до отдельного согласования владельца не запускаются и не изменяют `Книга/Калькулятор_ставки_часа.xlsx`. Они объединены командой `python3 Инструменты/карта.py`; её запуск — осознанный шаг синхронизации, а не часть обычного веб-гейта.

| Файл | Роль в пересборке книги |
|---|---|
| `карта.py` | Единственный оркестратор полного согласованного прогона. |
| `справочник_в_отчёт.py` | Публикует утверждённую пользовательскую часть глоссария в отчёт/PDF. |
| `мигрировать_каталоги_в_чистую.py` | Пересобирает лист значений каталога из фактического CAT `calc.html`. Несмотря на слово «мигрировать», это текущий шаг `карта.py`. |
| `собрать_интерфейс.py` | Строит лист «Интерфейс» по технической разметке страниц. |
| `собрать_тексты.py` | Строит лист пользовательских текстов по `data-t`. |
| `собрать_css.py` | Строит лист CSS-деклараций фактических web-страниц. |
| `синхронизировать_названия_calc.py` | Сводит названия строк чистого `calc` с глоссарием. |
| `синхронизировать_рабочее_место.py` | Зеркалит ветки рабочего места и его эффективное исключение. |
| `синхронизировать_обучение.py` | Зеркалит обучение и его эффективное исключение. |
| `синхронизировать_сайт.py` | Зеркалит две ветки сайта и его эффективное исключение. |
| `синхронизировать_финансовое_ядро_чистой.py` | Собирает сценарное финансовое ядро Excel по реальному `calc()`. |
| `перевести_финансовое_ядро_на_совместимые_формулы.py` | Внутренний шаг предыдущего скрипта: переводит современную Excel-математику в совместимые формулы. |
| `собрать_полный_отчёт.py` | Строит лист полного отчёта по контракту и харнессу. |
| `собрать_программу_лояльности.py` | Строит лист программы лояльности из правил `report.html`. |
| `собрать_00_читать.py` | Пересобирает навигационный лист `00_Читать`. |
| `пересчитать_чистую_книгу.py` | Пересчитывает временную копию LibreOffice и сверяет с `calc()`. |
| `проверить_сценарии_чистой_книги.py` | Дополнительно сравнивает сценарии книги с харнессом; запускать после согласованной пересборки. |

## 4. Публикационный контур

| Файл | Роль | Статус |
|---|---|---|
| `создать_pdf_отчёта.py` | Создаёт три контрольных PDF отчёта в headless Chromium. | Нужен при работе по открытой З-016 и перед PDF-публикацией. |
| `создать_pdf_прайса.py` | Создаёт контрольный PDF прайса. | Нужен при PDF-публикации прайса. |

## 5. Операционные правила

1. Для обычной правки HTML/расчёта запускается только зелёный гейт из раздела 1. Он не трогает книгу, архив и `Веб/Части/`.
2. Изменение формулы или чистого старта: сначала browser-default, затем при намеренном новом результате `--write-snapshot`, затем `демо.py`, затем зелёный гейт.
3. Инструменты раздела 3 запускаются только после отдельного решения синхронизировать основную книгу.
4. Инструменты раздела 4 запускаются только для PDF-контроля; они не заменяют web-проверки.
5. `--legacy` полезен как исторический аудит, но его красный результат не блокирует принятие изменения действующего веб-контура.
