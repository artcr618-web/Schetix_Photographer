## 1. ОБЩАЯ КАРТИНА

### 1.1. Что такое Счётикс

Сервис юнит-экономики для фотографа. Человек проходит анкету из 20 вопросов — и получает персональный отчёт: желаемая ставка часа, ставка «в ноль» (точка безубыточности), базовая ставка для услуг вне съёмки, доход в час на руки, разбивка времени, разбивка расходов, сравнение 7 налоговых режимов 2026 года, программа лояльности, подробная детализация, справочник понятий. Отдельно собирается персональный прайс.

Принцип: **все расчёты — только в браузере**. Никуда данные не отправляются (строка «Ваши данные остаются у вас» — правда: весь код — статический HTML+JS, серверных вызовов для расчёта нет).

### 1.2. Цепочка данных (единственная правильная)

```
index.html (вход) → calc.html (анкета) → функция calc() → объект d
   → saveReport(d) в localStorage['phc_report'] (+ запасной путь ?data= base64)
   → report.html (loadData) → render() → экран / печать / PDF
   → price.html (loadData из того же хранилища) → персональный прайс
```

Порядок никогда не меняется: изменение значения сначала меняет `calc()`, затем `d`, затем HTML-отчёт, и только потом PDF (см. `Документация/АРХИТЕКТУРА_ДАННЫХ_PDF.md`). PDF — не источник данных, а печать HTML.

### 2.2. Алгоритмы страницы

1. **Переход с реферальной меткой.** `адрес()` = `'calc.html'` + `location.search` целиком — метка `?ref=…` доходит до анкеты и блока оплаты.
2. **«Уже начинал — сразу в анкету».** По нажатию кнопки в `localStorage['phc_seen']='1'`. При загрузке: если метка есть и в адресе нет `?hello=1` — `location.replace(calc.html)`. Метка ставится по клику, а не при загрузке (чтобы человек, закрывший вкладку не начав, снова попадал на обложку). `?hello=1` — принудительный показ обложки.
3. **Подсветка лепестков** — mouseenter/mouseleave на `.pet` (классы `.hot`/`.dim`).

### 3.4. АЛГОРИТМ `calc()` — полностью (строки ~3264–3615)

**Шаг 1. Календарь и время.**
```
CAL=365, WEEKEND=104, HOLI=14, WD=247, VAC=20, SICK=8, EFF=7, WM=11, MO=12
ND = WD − VAC − SICK = 219                      # рабочих дней
NT = ND × EFF = 1533                            # эффективное время (7 ч/дн)
workHours = ND × 8 = 1752                        # «как у наёмного» — для сравнения
promo = promo_per_day × ND = 438                 # поиск заказов
accT  = (acc_mode=self ? acc_per_quarter×4 : 0)  # учёт: 12, либо 0
side  = promo + accT = 450                       # операционное время
```
**Шаг 2. Резерв времени (fm).**
```
fmT = (fm_on ? pool_gross × fm_pct : 0);  pool_gross = NT − side = 1083
```
Ограничение (вводится в код): `side` не может съесть больше 80% NT — при превышении promo/accT масштабируются пропорционально так, чтобы `side ≤ 0.8·NT`.
```
pool = pool_gross − fmT = 1083                   # проектное время
```

**Шаг 3. Проект (S × (1+K) + cl).**

### 3.5. `recalc()` и пересчёт на лету

`recalc()` = `обновитьСклонения + обновитьПодсветкуПолей + sumF по 8 формам + лимит()`. Вызывается на каждый input/change/range; при `scroll` — тоже `лимит()` (пассивно).

### 3.6. Лимиты режимов и автоподбор (2026)

```
ЛИМИТЫ = { npd/npd4/npd5/npd6: 2 400 000 «НПД»,
           usn6/usn15: 20 000 000 «УСН без НДС»,   # порог НДС, ФЗ-228
           ausn8/ausn20: 60 000 000 «АУСН» }
```

**`подобрать()`** (автоподбор, чекбокс `tax_auto`): сравнивать режимы по «на руки» бессмысленно — на руки всегда выходит ровно желаемый доход. Правильный признак: **сколько нужно ЗАРАБОТАТЬ**. Для каждого из 5 режимов ставит select, считает `calc()`, отбрасывает не влезшие в лимит, берёт минимальную `d.R`; если ни один не влез — оставляет выбор человека. При автоподборе карточка режима блокируется (`.tax-auto-lock`), живой только зелёный переключатель.

**`лимит()`** (на каждый пересчёт):
1. Выручка переросла НПД → по закону режим слетает. Код автоматически переставляет на `usn6` (проверено: среди ИП-режимов даёт больше всех на руки при любой выручке выше лимита НПД), флаг `ПЕРЕКЛЮЧЕНО=true`, предупреждение в плашке, селект остаётся открытым — человек может выбрать сам.
2. Пока выручка > 2,4 млн, пункт «Самозанятый» в select **прячется** (`hidden/disabled`) — иначе это «заведомо невозможный вариант».
3. Если НПД был заменён автоматически: коварно переключает в npd, считает выручку именно в НПД, возвращает выбор обратно; если теперь укладывается — `sel.value='npd'`, флаг `ВОЗВРАЩЕНО_НПД=true` (зелёное подтверждение).
4. Плашка `.lim` — только «подходит/не подходит», без цифр (форма, а не результат).

**Полоса `полоса()`** (`.limbar`, фиксированная внизу): дублирует сообщение, когда блока режима на экране нет (расходы — 10 блоков ниже). Видна 12 секунд (`ДЛИТЕЛЬНОСТЬ_ПОЛОСЫ=12000`), закрывается крестиком (`ПОЛОСА_ЗАКРЫТА`), не показывается при автоподборе и при отключённых налогах; повторные пересчёты не перезапускают таймер (сравнение `data-state`).

### 3.7. Валидация перед расчётом `проверитьПоля()`

Порядок: `income_month` (целое число без копеек, 10 000…3 000 000), `current_rate` (целое, ≥0, ≤1 000 000 — честный ноль допустим), `frames_out` (целое 1…1000), `shutter_per_hour` (целое 1…1000), затем обязательные `income_month` и `shoot_manual` (>0). Введённое значение никогда не «исправляется молча»: тост с конкретной причиной + `подсветить(поле)` (скролл к карточке, мигание `.схх-мигание` 2,6 с, фокус).

**Кнопка «Рассчитать» (`go`):**
1. `проверитьПоля()` → тост+подсветка и выход;
2. `calc()`; если `sh ≤ 0` — тост «Не получается посчитать: в году не осталось часов на съёмку» + подсветка виновника (FormPromoTime/FormClientTime);
3. анимация `#ld`: кольцо 200px (dasharray 578), 7000 мс, 7 стадий `ST` (0% «Считаем рабочее время» → 14% «Распределяем часы» → 30% «Считаем износ техники» → 46% «Собираем расходы» → 60% «Подбираем налоговый режим» → 76% «Раскладываем каждый час» → 90% «Формируем отчёт»);
4. после 100%: `saveReport(res)`, `saveState()`, `location.href='report.html'`.

### 3.8. Передача результата и состояния

```

restoreState(): сначала восстанавливает ЧИСЛО СТРОК таблиц и комиссий (иначе обход
```

### 3.9. Сбросы (три уровня)

1. **Общий** (`сбросить()`, кнопка `reset` + иконки `trustResetBtn`/`topResetBtn`): первый клик — предупреждение (кнопка краснеет, 5 с на подтверждение), второй — исполнение. Порядок: таблицы → заново из CAT; банк-комиссии → очищены; удалённые строки (`field-row-removed`) → возвращены; поля → значения из снимка `ПОУМОЛЧАНИЮ` (снят ПОСЛЕ заполнения таблиц CAT и первого recalc, ДО иконок отката); `применитьСостояния()` (радио-подсветка, исключающие галочки, подблоки веток ws/site/acc, ползунки); `phc_state` и `phc_report` удалены; `recalc()`; событие `defaultsreset` гасит иконки отката.
2. **Блочный** (иконка ↺ у заголовка каждой карточки, `.rst-ic`): активна только когда в блоке есть отклонение от снимка и блок не выключен (`.off`/`.taxdim`/`.tax-auto-lock`/выключенный резерв). Откатывает поля, таблицы и состояния именно своей карточки; **галочку «не учитывать» не трогает** (это решение о судьбе блока). В составной карточке (B015b банк) — две кнопки: своя таблица регулярных платежей и своя «комиссии».
3. **Форматирование денег**: `форматироватьВсеДеньги()` — разрядные пробелы; денежные поля `type=text` (чтобы браузер не удалял пробелы), спиннеры number скрыты.

### 13.4. price.html — полный алгоритм (глубокий просмотр)

**Загрузка**: `?data=` (base64, с decodeURIComponent — иначе atob молча падает в DEMO) → `phc_report` → свой DEMO (упрощённый: Ny 1 307 988, R 2 042 538, taxAll 106 934, aq 57 744 — см. находку 13.6).

**Опорные цифры**: `СТАВКА = round(rateWorkFull)` (готовая цифра расчёта, решение 06.09; fallback `round(R/NT)`, запас 1332); `ЧАС_СЪЁМКИ = round(R/sh)` (запас 9430); `СЪЁМОЧНЫХ_ЧАСОВ_В_ГОДУ = d.sh`; `ВЕДЕНИЕ_ЗАКАЗА = 40/60` (один раз на заказ, в T1 не идёт — час уже в съёмке); `СРОЧН = 2` (двойной тариф только на работу за столом); `ОБР_НА_ЧАС = 3`; `МИН/МАКС_ЧАС = 1/24`; `ГОТОВНОСТЬ_СЪЁМКИ = 3` (дня, 05.09); `ЧАСОВ_КОМПЕНСАЦИИ_ДНЯ = 6` (день в отъезде = ставка × 6 ч, решение 06.09: из 7 эффективных часов 1 заложен в съёмку).

**Режимы строк** (`data-mode`):
- `vol` (коммерческая съёмка): ступени S0/+2/+4/+6; `час(S) = (S(1+K)+cl)·hp/S`; срочный проект = `(S(1+2K)+cl)·hp`; скидка = `1 − час(S)/час(база)`, база — ступень с минимальной длительностью (с учётом ручной правки); проценты от ОКРУГЛЁННЫХ цен; при `discP>0` — сверху `×(1−discP)`; блок прячется, если нет `pool/R`.
- `cons` (консультация): целые часы × СТАВКА.
- `turnkey` (чистая съёмка): часы × ЧАС_СЪЁМКИ (без поста и срочности).
- услуги по ставке: `(часы×кол-во + (data-mode=order ? 40/60 : 0)) × СТАВКА`; без столбца времени — поле заполняет фотограф.
- `rent` (аренда): `стоимость/срок ÷ (sh × интенсивность/100) × (1+добавка/100)`.

**Сетка печатных таблиц** (единая): `СЕТКА_УСЛУГ = {40/17/13/16/14%}`, границы 28·46·66·84·100; набор колонок из `data-cols` (`Столбцы_ВСЕ = name/time/qty/price/ready/fast`); у «Прочих услуг» — name/time/price/fast, у «Аренды» — только name+price+свои поля (стоимость/срок/интенсивность/добавка).

**Пользовательские блоки** (05.09): предустановленные `pshoot1` «Прочие услуги» (строка «Продюсирование съёмки», 1 ч) и `pshoot0` «Аренда дополнительного оборудования» (4 строки-примеры владельца: R6 II 166 999/3 г., RF 24–105 130 999/5, SanDisk ×2 13 980/2, DJI Ronin RS 4 Pro 85 000/4 — все 100%/40%); «Видеосъёмка» и кнопка «Добавить блок» убраны 05.09, вместо — «Копировать блок» ⧉ у любого блока; режим «отдельным заказом» удалён 05.09 (старые блоки идут в общий список); блоки встают перед «Логистикой» (она последняя, 06.09); уведомление «Аренда и использование дополнительного оборудования» (текст владельца 06.09, рекомендация наценки 30–50%) — в печать и просмотр не идёт.

### 15.3. Взаимодействие блоков — цепочки

**Цепочка данных (главная)**:
```
ввод анкеты → calc() (13 шагов) → d (101 поле: answers + catalog + расчёты)
  → report.html (20 блоков) → печать/PDF (Chromium)
  → price.html (читает те же поля d, строит 4 блока цен)
  → Книга Excel (зеркало формул, сверка 15 сценариев)
```
Отчёт и прайс получают **готовый d** и не считают заново (RULE-001).
Сборщики `answers`/`catalog` внутри `calc()` решают, что попадает в
детализацию PDF (АРХИТЕКТУРА_ДАННЫХ_PDF: сценарии А–Г).
