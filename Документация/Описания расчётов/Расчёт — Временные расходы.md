# Расчёт — Временные расходы

Обновлено: 26 августа 2026.

Эталон понятия: лист `01_Глоссарий`, **№ 130 «Временные расходы»**.

> Время, которое специалист затрачивает на выполнение работы, взаимодействие с клиентами, организационные задачи и другие действия, связанные с профессиональной деятельностью.

---

## 1. Назначение

Показатель объединяет всё рабочее время специалиста, которое распределяется между выполнением проектов, операционными задачами, резервом времени и неэффективным рабочим временем.

В листе `Состав` показатель связан с техническим полем `workHours`.

Временные расходы измеряются в часах и не складываются с Финансовыми расходами в одну денежную сумму.

---

## 2. Состав понятия

Эталон состава — лист `Состав`:

1. Съёмочное время;
2. Время на постпродакшн;
3. Проектное клиентское время;
4. Поиск заказов;
5. Учёт;
6. Резерв времени на простой и форс-мажоры;
7. Неэффективное рабочее время.

Инвестиционное время учитывается отдельно и не входит в годовое рабочее время этого показателя.

---

## 3. Рабочий календарь

Константы 2026 года:

```javascript
WD = 247;   // рабочих дней производственного календаря
VAC = 20;   // рабочих дней отпуска
SICK = 8;   // рабочих дней болезни
EFF = 7;    // эффективных часов в рабочем дне
```

Чистые рабочие дни:

```javascript
ND = WD - VAC - SICK;
```

```text
247 − 20 − 8 = 219 рабочих дней
```

Полное рабочее время:

```javascript
workHours = ND * 8;
```

```text
219 × 8 = 1 752 ч/год
```

Эффективное рабочее время:

```javascript
NT = ND * EFF;
```

```text
219 × 7 = 1 533 ч/год
```

Неэффективное рабочее время:

```javascript
idle = ND * (8 - EFF);
```

```text
219 × 1 = 219 ч/год
```

Проверка:

```text
1 533 + 219 = 1 752 ч
```

---

## 4. Операционные временные расходы

### 4.1. Поиск заказов

```javascript
promo = promo_per_day * ND;
```

По умолчанию:

```text
2 ч/день × 219 дней = 438 ч/год
```

Если блок исключён, `promo = 0`.

### 4.2. Учёт

При самостоятельном учёте:

```javascript
accT = acc_per_quarter * 4;
```

По умолчанию:

```text
3 ч/квартал × 4 = 12 ч/год
```

Если учёт ведёт нанятый специалист:

- `accT = 0`;
- вместо времени возникает денежный расход Бухгалтерии.

### 4.3. Ограничение операционного времени

Поиск заказов и самостоятельный Учёт не могут занять больше 80% Эффективного рабочего времени:

```javascript
ПРЕДЕЛ_СТОРОННЕГО = NT * 0.8;
side = promo + accT;
```

Если предел превышен, обе части пропорционально уменьшаются до 80% `NT`.

Ограничение не делает ввод пользователя правильным или реалистичным, но не позволяет расчёту получить отрицательное проектное время.

---

## 5. Резерв времени

После операционных временных расходов:

```javascript
gross = NT - side;
```

Если включён Резерв времени на простой и форс-мажоры:

```javascript
fmT = gross * fm_pct;
```

По умолчанию резерв выключен:

```text
fmT = 0 ч
```

Резерв уменьшает время, доступное для проектов, но остаётся частью Временных расходов, которую необходимо компенсировать стоимостью услуг.

---

## 6. Проектное время

Эталон понятия: глоссарий № 66.

> Общее время, которое специалист затрачивает на выполнение всех съёмочных проектов в течение определённого периода, включая съёмочное время, время на постпродакшн и проектное клиентское время.

В `calc()`:

```javascript
pool = gross - fmT;
```

По умолчанию:

```text
1 533
− 438 поиск заказов
− 12 учёт
− 0 резерв времени
= 1 083 ч/год
```

Проектное время может показываться за год, месяц, неделю или другой выбранный период.

---

## 7. Длительность одного съёмочного проекта

```javascript
pt = S * (1 + K) + cl;
```

Где:

- `S` — Минимальный заказ в съёмочных часах;
- `K` — часы постпродакшна на один час съёмки;
- `cl` — Проектное клиентское время на проект.

По умолчанию:

```text
1 час съёмки
+ 3 часа постпродакшна
+ 1 час проектного клиентского времени
= 5 часов на проект
```

Если Минимальный заказ равен двум часам:

```text
2 часа съёмки
+ 6 часов постпродакшна
+ 1 час проектного клиентского времени
= 9 часов на проект
```

Проектное клиентское время не умножается на длительность съёмки.

---

## 8. Количество проектов и проектные составляющие

Количество проектов:

```javascript
py = pool / pt;
```

По умолчанию:

```text
1 083 ÷ 5 = 216,6 проекта в год
```

Съёмочное время:

```javascript
sh = py * S;
```

```text
216,6 × 1 = 216,6 ч/год
```

Время на постпродакшн:

```javascript
post = sh * K;
```

```text
216,6 × 3 = 649,8 ч/год
```

Проектное клиентское время:

```javascript
clT = py * cl;
```

```text
216,6 × 1 = 216,6 ч/год
```

Проверка времени проектов:

```text
216,6 + 649,8 + 216,6 = 1 083 ч
```

## 10. Ветки и выключатели

### Минимальный заказ

Изменяет время одного проекта, количество проектов, Съёмочное время и Время на постпродакшн.

### Постпродакшн

Изменяет коэффициент `K` и распределение проектного времени.

### Проектное клиентское время

При исключении блока:

```text
cl = 0
clT = 0
```

Освободившееся время переходит в другие проектные составляющие через увеличение количества проектов.

### Поиск заказов

При исключении:

```text
promo = 0
```

### Учёт

Выбор между самостоятельной и денежной веткой изменяет одновременно Временные и Регулярные расходы.

### Резерв времени

Снятая галочка даёт эффективный ноль. Установленная галочка использует сохранённый процент.

## 11. Нулевые и предельные случаи

1. Если `S = 0`, Съёмочное время равно нулю; обязательное поле должно остановить переход в отчёт.
2. Если время проекта равно нулю, количество проектов принимается равным нулю, деление не выполняется.
3. Если операционные расходы превышают 80% `NT`, применяется ограничитель.
4. Выключенная необязательная временная часть даёт эффективный ноль.
5. Отрицательный пользовательский ввод должен отклоняться валидацией; полная система ограничений остаётся задачей З-035.

---

## 12. Что не входит во Временные расходы

Не входят:

- Инвестиционное время;
- отпускные и больничные дни как рабочие часы — они заранее вычтены из рабочего календаря;
- Финансовые расходы;
- Налоги;
- Эквайринг;
- денежный Резервный фонд.

Инвестиционное время Обучения и самостоятельного создания Сайта компенсируется отдельным денежным расчётом.

## 14. Связанные показатели

- Рабочее время — календарный фонд рабочих часов после отпуска и больничных.
- Эффективное рабочее время — Рабочее время без Неэффективного рабочего времени.
- Операционное время — Поиск заказов и Учёт в текущем `calc()`; другие операционные составляющие могут требовать отдельной модели.
- Проектное время — время выполнения всех съёмочных проектов за выбранный период; в `calc()` это `pool`.
- Длительность одного съёмочного проекта — промежуточный показатель `pt`, рассчитанный из длительности съёмки, постпродакшна и проектного клиентского времени.
- Инвестиционное время — отдельная группа, не включённая в `workHours`.

---

## 15. Округление

Внутри расчёта время хранится с полной точностью. Пользователю время обычно показывается с одной десятичной либо целым числом в зависимости от поверхности. Округлённое отображение не возвращается в формулы.

---

## 16. Проверки

Штатный сторож проверяет:

- операционное время + резерв времени + годовой фонд проектов = Эффективное рабочее время;
- Съёмочное время + Время на постпродакшн + Проектное клиентское время = время проектов;
- Эффективное + Неэффективное рабочее время = полное рабочее время;
- работу ограничителя 80%;
- длительность проекта при `S` от 0,5 до 8 часов;
- загрузку необходимого, текущего и безубыточного сценариев;
- нулевую длительность съёмки.

## 10. Актуальный план календаря REPORT-B008

**Обновлено: 27 сентября 2026.**

Календарь в `Веб/report.html` не является вторым расчётным ядром. Он получает готовый объект `d.projectPlan` из `Веб/calc.html` и только размещает его части по временным слотам.

### 10.1. Формирование горизонта в `calc.html`

Для плана используются:

```javascript
M = 1 + K;                         // съёмка + постпродакшн на 1 ч съёмки
ptMin = S * M + cl;                // минимальный полный проект
projectWeek = pool / NW;           // проектная ёмкость одной рабочей недели
weeks = max(1, ceil(ptMin / projectWeek));
periodPool = projectWeek * weeks;
projects = floor(periodPool / ptMin);
```

- `S` — минимальная продолжительность съёмки из анкеты, включая 0,5 ч;
- `projects` — только целые проекты; отдельный короткий «огрызок» не создаётся;
- `cl` начисляется ровно один раз на каждый сформированный целый проект;
- съёмка и обработка занимают всю оставшуюся проектную ёмкость периода:

```javascript
clientPeriod = projects * cl;
shootPeriod = (periodPool - clientPeriod) / M;
postPeriod = shootPeriod * K;
```

### 10.2. Распределение хвоста съёмки

Каждый проект начинается с `S`. Остаток `shootPeriod - projects * S` распределяется между уже созданными проектами:

1. Полные блоки по 0,5 ч делятся максимально равномерно между всеми проектами.
2. Первые проекты получают по одному дополнительному полчасу, пока блоки не закончатся.
3. Остаток меньше 0,5 ч без округления присоединяется к первому проекту.
4. Последней защитной поправкой первый проект доводится до точной суммы `shootPeriod`; это устраняет только машинную погрешность чисел с плавающей точкой.

Следовательно, план не теряет дробный хвост и не создаёт дополнительную короткую съёмку.

### 10.3. Строка «Съёмочных проектов» в таблице времени

Проекты — дискретные заказы, а не часы. Поэтому в колонке «За 1 час съёмки» ставится прочерк. Для недели, месяца и года отчёт показывает только целые завершённые проекты: `floor(py / период)`. Дробная часть уже присоединена к продолжительности существующих проектов по правилу 10.2 и не превращается в десятые проекта или в самостоятельную короткую съёмку. Например, при 4 проектах в неделю DEMO показывает 14 проектов в месяц и 175 за год.

### 10.4. Что делает `report.html`

`REPORT-B008` показывает общую шкалу 08:00–19:00, но рабочая ёмкость рассчитывается **по каждому дню**, а не искусственно заполняется до нижней границы сетки:

- обычный день — это **8 рабочих часов и обед 12:00–13:00**: доступные рабочие интервалы идут с 08:00 до 17:00. Ячейки 17:00–19:00 в таком столбце обозначают окончание смены, а не свободные либо обязательные часы;
- съёмочный проект добавляет ровно **2 часа логистики**: один непосредственно перед съёмкой и один непосредственно после неё. Поэтому съёмочный день имеет 10 рабочих часов плюс обед и продолжается до 19:00. Если съёмки нет, этих двух часов нет и день на два часа короче;
- проекты берутся из `projectPlan.projects`, сортируются по длительности съёмки и сохраняют точные финансовые часы; дни для съёмок чередуются в порядке ПН, СР, ПТ, ВТ, ЧТ с циклическим сдвигом для следующего проекта;
- при съёмке до 4 ч обед ставится перед выездом на 11:00–12:00, входящая логистика — на 12:00–13:00, а съёмка начинается в 13:00. При съёмке более 4 ч логистика занимает 11:00–12:00, обед 16:00–17:00 разрывает длинную смену;
- календарная проекция использует **точную** длительность съёмки из `projectPlan`, включая дробные минуты: отчёт не округляет её вверх и не меняет `d`. Округление времени заказчиком на площадке трактуется как дополнительная выручка фотографа, а не как основание продлевать собственный рабочий план. Логистика начинается в точную минуту окончания съёмки и может занимать части двух соседних ячеек;
- сервисные часы — обед и логистика — не являются оплачиваемой расчётной ёмкостью. Регулярные и проектные роли занимают только оставшиеся **доступные** окна;
- порядок алгоритма после резервирования съёмочной связки: **управление → учёт → работа с клиентом → ежедневное продвижение → форс-мажоры → обработка → рабочие паузы**. Съёмки и два обязательных логистических часа резервируются структурно заранее, чтобы последующие роли не могли их сдвинуть;
- продвижение — ежедневная роль: объём `projectPlan.regular.promo` поровну делится на все рабочие дни горизонта. При стандартных 2 ч/день первая полоса стоит утром, вторая — в последнем вечернем рабочем окне конкретного дня: 16:00–17:00 в обычном дне и 17:00–18:00 в съёмочном;
- управление планируется недельными блоками: сначала единый блок до 2 ч в понедельник. Если недельный объём больше 2 ч, следующие блоки до 2 ч последовательно занимают вторник, среду, четверг и пятницу; только после первого обхода дней начинается второй. Поэтому типовые 2 ч/нед не разбиваются между понедельником и вторником;
- форс-мажор ставится перед обработкой одним последовательным блоком. Если его точное время заканчивается внутри часа, свободный остаток **сразу занимает обработка** — так же, как обработка закрывает дробную логистику после съёмки. Оставшаяся обработка затем собирается в **крупнейшие доступные блоки**. У неё остаётся не более одного собственного дробного хвоста за план; ей не назначается фиксированная декоративная ячейка и она не обязана появляться ежедневно;
- рабочие паузы ставятся последними и занимают **не более 1 часа суммарно в день**. Они никогда не открывают день и не ставятся до обеда. Их единственная допустимая дробность — закрыть единственный послеобеденный хвост **обработки** до целого часа; пауза не заполняет логистику или форс-мажор напрямую. Если после соблюдения этих правил времени не хватает, календарь показывает точный неразмещённый остаток, а не скрывает его смешением ролей или изменением `d`;
- **одна ячейка не смешивает две обычные рабочие роли.** Единственное сервисное исключение — непрерывная пара «съёмка → логистика», когда дорога начинается в `:30`;
- состав неполного часа рисуется **слева направо** в фактической последовательности. Логистика, включая её часть после съёмки, всегда остаётся белым сервисным сегментом с нейтральным контуром, а не получает цвет форс-мажора. В разделённой ячейке иконки камеры, логистики и рабочей паузы ставятся внутри своих половин. Для части `Рабочие паузы` используется утверждённая иконка неэффективного рабочего времени — две вертикальные планки; в полной ячейке она показывается вместе с названием. Все иконки календаря имеют единый размер 24×24. Пустая либо нерабочая ячейка остаётся полностью прозрачной: без заливки, контура и прочерка.

Календарь не переписывает `d`, не пересчитывает количество заказов и не меняет значения, выданные `calc.html`.
