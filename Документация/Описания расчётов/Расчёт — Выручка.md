# Расчёт — Выручка

Обновлено: 26 августа 2026.

Эталон понятия: лист `01_Глоссарий`, запись **№ 40 «Выручка»**.

> Общая сумма денежных средств, которую специалист получает от продажи своих услуг за определённый период, включая суммы, предназначенные для покрытия всех расходов и обязательных платежей, налогов, стоимости оборудования и его амортизации, банковских расходов, резервов на отпуск, развитие, обучение и другие предусмотренные расчётом затраты, а также доход специалиста.

«Общая выручка» — пользовательская подпись на главном экране. Утверждённое понятие называется **«Выручка»**.

---

## 1. Назначение

Выручка показывает, какую общую сумму специалисту необходимо получить от клиентов, чтобы после всех предусмотренных расчётом затрат и отчислений у него остался Желаемый доход.

Это годовой расчётный показатель. Месячная Выручка получается делением годовой Выручки на 12, но отдельным понятием не является.

---

## 2. Состав понятия

Эталон состава — лист `Состав`, строка с ID `R`:

1. Желаемый доход;
2. Финансовые расходы;
3. Налоги;
4. Эквайринг;
5. Инвестиционное время — в активной ветке самостоятельного создания сайта;
6. Резерв на развитие — если включён;
7. Резерв на программу лояльности — если включён.

Резерв на отпуск отдельно к Выручке не прибавляется: он находится внутри Желаемого дохода.

### 2.1. Желаемый доход

Пользователь вводит месячное значение `income_month`. Для годового расчёта `calc()` получает:

```javascript
Ny = V('income_month') * 12;
```

По умолчанию:

```text
110 216 × 12 = 1 322 592 ₽/год
```

### 2.2. Финансовые расходы

```javascript
C = amort + vari;
```

По умолчанию:

```text
Финансовые вложения       278 687,78 ₽
Регулярные расходы        283 980,00 ₽
────────────────────────────────────
Финансовые расходы        562 667,78 ₽
```

Подробный состав этих групп закреплён на листе `Состав` и в их собственных паспортах.

### 2.3. Налоги

Налог рассчитывается функцией `taxOf(Rx)` от самой Выручки. Формула зависит от налогового режима, минимального налога, страховых взносов и установленных ограничений.

### 2.4. Эквайринг

Доля эквайринга и дополнительных процентных банковских комиссий:

```javascript
a = acqPart + extraBankPart;
aq = R * a;
```

По умолчанию эквайринг составляет 2,7% при 100% безналичных оплат:

```text
2 042 534,97 × 2,7% = 55 148,44 ₽
```

### 2.5. Инвестиционное время

Если сайт заказан у специалистов, его годовая стоимость находится внутри Финансовых вложений. Если сайт создан самостоятельно, денежная компенсация Инвестиционного времени считается как доля Выручки:

```javascript
sdiv = site_hours / (site_life * NT);
goalSelfSiteCost = R * sdiv;
```

По умолчанию эта ветка выключена. При самостоятельном сайте из демо-набора компенсация составляет 15 269,74 ₽/год.

### 2.6. Резервы

```javascript
goalFund = R * fundP;
goalDiscountReserve = R * discP;
```

Оба резерва по умолчанию выключены. Это отдельная группа, а не Финансовые расходы.

---

## 3. Фактический алгоритм `calc()`

### 3.1. Доля Выручки после процентных изъятий

```javascript
D = 1 - a - sdiv - fundP - discP;
if (D < 0.40) D = 0.40;
```

Границы:

- эквайринг и дополнительные банковские проценты — не более 10%;
- Резерв на развитие — не более 20%;
- Резерв на программу лояльности — не более 15%;
- после всех процентных изъятий должно оставаться не менее 40% Выручки.

### 3.2. Уравнение

`calc()` ищет такую Выручку `R`, при которой выполняется тождество:

```text
R × D − Финансовые расходы − Налоги(R) = Желаемый доход
```

В развёрнутом виде:

```text
Выручка =
Желаемый доход
+ Финансовые расходы
+ Налоги
+ Эквайринг
+ компенсация Инвестиционного времени
+ Резерв на развитие
+ Резерв на программу лояльности
```

### 3.3. Почему используется численный поиск

Для НПД уравнение можно было бы решить простой формулой, но УСН и АУСН содержат:

- фиксированные и дополнительные страховые взносы;
- порог дополнительного взноса;
- предел взносов;
- минимальный налог;
- налоговую базу «доходы минус расходы»;
- взаимозависимость базы и страховых взносов.

Поэтому используется один алгоритм для всех режимов:

```javascript
function выручкаПод(цель, доля) {
  var lo = 0, hi = 1e9, m;
  for (var i = 0; i < 90; i++) {
    m = (lo + hi) / 2;
    if (m * доля - C - taxOf(m) < цель) lo = m;
    else hi = m;
  }
  return lo;
}
```

Для Выручки:

```javascript
R_ = sh > 0 ? выручкаПод(Ny) : 0;
```

90 итераций дают точность существенно выше копейки.

## 6. Включаемые ветки

| Ветка | Что происходит |
|---|---|
| Резерв на развитие включён | `fundP` уменьшает `D`, Выручка увеличивается, чтобы Желаемый доход сохранился |
| Резерв программы лояльности включён | `discP` уменьшает `D` по тому же принципу |
| Сайт создан самостоятельно | денежная амортизация сайта равна нулю, вместо неё действует `sdiv` и компенсация Инвестиционного времени |
| Банк исключён | регулярные банковские расходы и процентные комиссии получают эффективный ноль |
| Налоги выключены | `taxOf()` возвращает ноль во всех сценариях |

Примеры:

- Резерв на развитие 15%: Выручка 2 438 887,17 ₽; резерв 365 833,08 ₽.
- Резерв программы лояльности 10%: Выручка 2 290 716,62 ₽; резерв 229 071,66 ₽.
- Самостоятельный сайт: Выручка 2 048 244,33 ₽; компенсация Инвестиционного времени 15 269,74 ₽.

## 7. Нулевые и предельные случаи

1. Если съёмочных часов нет (`sh = 0`), Выручка принудительно равна нулю; анкета не должна пропустить пользователя в отчёт.
2. Отрицательные процентные значения ограничиваются нулём.
3. Процентные значения ограничиваются установленными максимумами.
4. Если итоговая доля `D` меньше 40%, применяется нижняя граница 40%.
5. Отрицательная Выручка не допускается: поиск начинается с нуля.
6. Верхняя техническая граница поиска — 1 млрд ₽.

## 8. Округление

Внутри `calc()` Выручка хранится с полной точностью:

```text
2 042 534,9739462414 ₽
```

Пользователю показывается целый рубль:

```text
2 042 535 ₽
```

Округлённое отображение не возвращается в формулы.

## 10. Родственные показатели

- Ставка часа съёмки = Выручка ÷ Съёмочное время.
- Базовая ставка = Выручка ÷ Эффективное рабочее время.
- Стоимость съёмочного проекта как промежуточная величина = Выручка ÷ количество проектов.
- Точка безубыточности использует ту же функцию поиска при нулевой цели и без резервов.
- Финансовый результат необходимого сценария = Выручка − все эффективные затраты.

Эти показатели не входят в лист `Состав`, если являются самостоятельными формулами, а не группирующими понятиями.

## 11. Проверки

Штатный сторож проверяет:

- «Выручка минус все затраты = Желаемый доход» для семи налоговых режимов;
- сценарии с резервами;
- сценарий без налогов;
- самостоятельный сайт;
- исключённый банк;
- предельные проценты;
- соответствие DEMO настоящей функции `calc()`;
- соответствие значений книги и анкеты.
