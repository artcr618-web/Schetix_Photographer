# АЛГОРИТМЫ

Пошаговые сценарии на каждый повторяющийся случай. Команды выполняются
из папки `/home/user/schetix`, если не сказано иначе.

Общее правило для всех сценариев: **последний шаг — проверка**.

```bash
python3 Инструменты/проверить.py schetix   # «упало» должно быть 0
```

---

## 1. Добавить новое понятие в справочник

Понятие видит человек: оно попадает в справочник отчёта и в подсказки анкеты.

1. Определение пишет **пользователь**. Своими словами не сочинять.
2. Вписать в словарь `СПРАВОЧНИК` — `Инструменты/таблицы_прототип.py`,
   по алфавиту, тем же стилем (строки по 90 символов, отступ два пробела).
3. Разнести по местам, где справочник используется:
   ```bash
   python3 Инструменты/справочник_в_отчёт.py   # REFD, СПР и карта СВЯЗЬ в отчёте и каркасе
   python3 Инструменты/подсказки.py            # подсказки в анкете
   ```
4. Если понятие должно появиться и в книге — добавить строку в лист
   `01_Глоссарий` книги (правим прямо в Excel).
5. Проверка.

## 2. Переименовать понятие

Самый опасный сценарий: название живёт в семи местах.

1. Убедиться, что переименование **согласовано**. Без «да» — не делать.
2. Пройти по всем местам:
   - `Инструменты/таблицы_прототип.py` — ключ в `СПРАВОЧНИК`, ключи в картах
     `СВЯЗЬ`, `СВЯЗЬ_БЛОК`, `СВЯЗЬ_05`, `СВЯЗЬ_06`, `СВЯЗЬ_08`, строки таблиц `в(...)`;
   - `Веб/calc.html` — заголовок блока, подпись `отв(...)`;
   - `Веб/report.html` и `Веб/Части/каркас.html` — легенда `REFLB`, строки таблиц;
   - `Инструменты/подсказки.py` — словарь `СЛОВА`;
   - лист `01_Глоссарий` книги.
   (Прежний пункт про `модель/группировки.py` снят 25.08 — скрипт удалён при чистке архива, история в git.)
3. Пересобрать: `справочник_в_отчёт.py`, `подсказки.py`, `демо.py`, `глоссарий.py`.
4. Проверка. Особенно смотреть на «ссылки таблиц ведут на существующие записи»
   и «report.html совпадает с каркасом».

Пример из практики: «Работа с клиентом» → «Проектная работа с клиентами» —
семь файлов, три генератора.

## 4. Изменить расчёт

Источник расчёта — функция `calc()` в `Веб/calc.html`.

1. Править `calc()`.
2. Посмотреть, что получилось, не открывая браузер:
   ```bash
   node Инструменты/харнесс.js /home/user/schetix '{}'
   ```
3. Пересобрать демо-набор отчёта (иначе отчёт без анкеты покажет старые числа):
   ```bash
   python3 Инструменты/демо.py
   ```
4. Обновить отчёт в книге и пересчитать её:
   ```bash
   python3 Инструменты/отчёт_в_книгу.py
   pip install formulas
   python3 Инструменты/пересчитать_книгу.py
   ```
5. Проверка. Смотреть столбец «Сходится» на листе `06b_Отчёт_полный`.

## 5. Править отчёт

1. Правку вносить **и в `Веб/report.html`, и в `Веб/Части/каркас.html`** —
   иначе упадёт проверка «report.html совпадает с каркасом».
2. Если правка касается справочника или карты ссылок — не руками,
   а `python3 Инструменты/справочник_в_отчёт.py`.
3. Проверка.

Помнить: у `calc.html` нет закрывающего `</body>` — скрипты вставлять
в конец файла.

## 6. Добавить или переписать лист книги

`openpyxl` при сохранении **теряет диаграммы**, поэтому книгу нельзя просто
открыть и записать. Работать через zip:

- добавить лист данными: `Инструменты/лист_в_книгу.py`;
- собрать лист отчёта: `Инструменты/отчёт_в_книгу.py`.

Читать книгу через `openpyxl` можно свободно — чтение ничего не портит.

После записи — пересчёт:
```bash
pip install formulas
python3 Инструменты/пересчитать_книгу.py
```

## 7. Найти, откуда берётся число

1. В отчёте у каждой строки детализации есть код: **0** — значение

2. Значение из настоящего расчёта:
   ```bash
   node Инструменты/харнесс.js /home/user/schetix '{}'
   ```

3. Формула и описание алгоритма — лист `06b_Отчёт_полный`, столбцы
   «Значение» и «Описание алгоритма».
4. Параметр книги и его зависимости — лист `calc` (121 именованный
   параметр) и `01_Глоссарий`.
5. Если число в книге и в расчёте разное — смотреть список расхождений
   в `Документация/03_ПОЛНАЯ_МЕХАНИКА_И_АЛГОРИТМЫ_25авг_2026.md`, Часть XII
   (прежде это был раздел 6 «НАЧНИ_ОТСЮДА» — документ в `Архив/Документация/`).

## 9. Проверить всё разом

```bash
python3 Инструменты/проверить.py schetix
```

115 проверок. Что они ловят: расхождение отчёта и каркаса, устаревший
демо-набор, битые ссылки таблиц на справочник, непересчитанные формулы книги,
несовпадение переключателей книги и анкеты, налоговые константы.

Замечание «записей справочника без ссылок» — не ошибка: часть записей
связывается динамически, проверка их не видит.

## 11. Сбросить состояние браузера при тестировании

Метки в `localStorage` живут вечно и мешают проверять окно благодарности:

```js
['phc_thx_paid','phc_thx_liked','phc_thx_когда','phc_thx_сколько']
  .forEach(k=>localStorage.removeItem(k));
sessionStorage.clear(); location.reload();
```

Состояние «оплата прошла» проверяется адресом `report.html?paid=1`.

## 13. Грабли, на которые уже наступали

| Грабли | Как обойти |
|---|---|
| `openpyxl` теряет диаграммы книги | писать листы только через zip |
| В JS `\w` не ловит кириллицу | явные классы `[А-Яа-яЁё]`, пробел как `[ ]+` |
| `calc.html` без `</body>` | скрипты вставлять в конец файла |
| Правило `.пункт .пункт` перебивало `.пункт.терм` | ограничено до `.пункт .пункт[data-таб]` |
| Второй массив справочника в отчёте жил своей жизнью | всё переносит `справочник_в_отчёт.py` |
| Скрипт читал лист, который сам же переписал | читать по заголовкам столбцов, а не по номерам |
| Прототипы в `Веб/Части/` расходятся с рабочими файлами | либо генератор, либо `Архив` |
