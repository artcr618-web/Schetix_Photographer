# АЛГОРИТМЫ

Пошаговые сценарии на каждый повторяющийся случай. Команды выполняются
из папки `/home/user/Schetix_Photographer`, если не сказано иначе.

Общее правило для всех сценариев: **последний шаг — проверка**.

```bash
python3 Инструменты/проверить.py /home/user/Schetix_Photographer
# «упало» должно быть 0
```

---

## 1. Добавить новое понятие в справочник

Понятие видит человек: оно попадает в справочник отчёта и в подсказки анкеты.

1. Определение пишет **пользователь**. Своими словами не сочинять.
2. Добавить утверждённую строку в лист `01_Глоссарий`; пользовательское понятие
   получает назначение `user`.
3. Выполнить полную пересборку:
   ```bash
   python3 Инструменты/карта.py
   ```
   Первый шаг карты автоматически публикует строки `user` в `report.html`,
   каркас и PDF-справочник.
4. Выполнить `сверить_глоссарий.py` и общую проверку.

---

## 2. Переименовать понятие

Самый опасный сценарий: название живёт в семи местах.

1. Убедиться, что переименование **согласовано**. Без «да» — не делать.
2. Начать с листа `01_Глоссарий`, затем проверить фактические подписи в
   `calc.html`, сборщик `d.answers`, строки детализации report и карты ссылок.
3. Выполнить `python3 Инструменты/карта.py`: справочник report/PDF будет
   опубликован из глоссария автоматически.
4. Проверить `report.html = каркас`, ссылки таблиц и отсутствие расхождений
   глоссария.

Пример из практики: «Работа с клиентом» → «Проектная работа с клиентами» —
семь файлов, три генератора.

---

## 3. Править глоссарий

Источник — лист `01_Глоссарий` книги, больше нигде. Отдельный HTML-вид
глоссария отменён 25.08.2026 по решению владельца; скрипт сборки удалён.

1. Внести утверждённую правку **в лист** — руками в Excel.
2. Запустить `python3 Инструменты/карта.py`: пользовательская часть справочника
   будет опубликована автоматически.
3. Запустить `сверить_глоссарий.py` и общую проверку.

---

## 4. Изменить расчёт

Источник расчёта — функция `calc()` в `Веб/calc.html`.

1. Править `calc()`.
2. Посмотреть, что получилось, не открывая браузер:
   ```bash
   node Инструменты/харнесс.js /home/user/Schetix_Photographer '{}'
   ```
3. Пересобрать демо-набор отчёта (иначе отчёт без анкеты покажет старые числа):
   ```bash
   python3 Инструменты/демо.py
   ```
4. Пересобрать все автоматические листы чистой книги и пересчитать её:
   ```bash
   python3 Инструменты/карта.py
   ```
   Команда обновляет `Значения_по_умолчанию`, `Интерфейс`, `Тексты`,
   `CSS_и_компоненты`, `Полный_отчёт`, `Программа_лояльности`, `00_Читать`
   и запускает совместимый пересчёт.
5. Проверка. Смотреть столбцы «Контрольное значение» и «Сходится» на чистом
   листе `Полный_отчёт`.

---

## 5. Править отчёт

1. Правку вносить **и в `Веб/report.html`, и в `Веб/Части/каркас.html`** —
   иначе упадёт проверка «report.html совпадает с каркасом».
2. Если правка касается справочника или карты ссылок — не руками,
   а `python3 Инструменты/справочник_в_отчёт.py`.
3. Проверка.

Помнить: у `calc.html` нет закрывающего `</body>` — скрипты вставлять
в конец файла.

## 6. Добавить или переписать лист книги

Чистая книга создана без диаграмм Excel, поэтому её генераторы могут безопасно
использовать `openpyxl`. После любой записи обязательно пересчитать книгу:

```bash
python3 Инструменты/пересчитать_чистую_книгу.py
```

Для полной пересборки всех автоматически получаемых листов:

```bash
python3 Инструменты/карта.py
```

Старая контрольная книга содержит три диаграммы. До архивирования её нельзя
сохранять обычным `openpyxl.save()`; старые ZIP-инструменты перемещены в
`Архив/Инструменты/` и не являются рабочим контуром.

## 7. Найти, откуда берётся число

1. В отчёте у каждой строки детализации есть код: **0** — значение
   по умолчанию, **А** — ответ анкеты, **Р** — результат расчёта.
2. Значение из настоящего расчёта:
   ```bash
   node Инструменты/харнесс.js /home/user/Schetix_Photographer '{}'
   ```

   `Полный_отчёт`.
4. Параметр книги и его зависимости — чистый лист `calc`; понятие и
   определение — `01_Глоссарий`.
5. Если число в книге и в расчёте разное — смотреть список расхождений
   в `Документация/03_ПОЛНАЯ_МЕХАНИКА_И_АЛГОРИТМЫ_25авг_2026.md`, Часть XII
   (прежде это был раздел 6 «НАЧНИ_ОТСЮДА» — документ в `Архив/Документация/`).

## 9. Проверить всё разом

```bash
python3 Инструменты/проверить.py /home/user/Schetix_Photographer
```

Проверок становится больше по мере миграции; норма — всегда `0 упало`.
Они ловят расхождение отчёта и каркаса, устаревший DEMO, битые ссылки,
непересчитанные формулы чистой книги, ошибки кэша, неполный контракт `d`,
нарушения RULE, сценарные расхождения и налоговые константы.

Замечание «записей справочника без ссылок» — не ошибка: часть записей
связывается динамически, проверка их не видит.

## 11. Сбросить состояние браузера при тестировании

Метки в `localStorage` живут вечно и мешают проверять окно благодарности:

```js
['phc_thx_paid','phc_thx_liked','phc_thx_когда','phc_thx_сколько']
  .forEach(k=>localStorage.removeItem(k));
sessionStorage.clear(); location.reload();
```

Состояние «оплата прошла» проверяется адресом `report.html?paid=1`.

## 12. Что ставить после перезапуска

Пакеты не входят в снимок рабочей папки:

```bash
pip install openpyxl
sudo apt-get install -y --no-install-recommends libreoffice-calc
cd Инструменты && npm ci
```

Пакет `formulas` больше не является движком чистой книги: полный пересчёт
выполняет `Инструменты/пересчитать_чистую_книгу.py` через LibreOffice.

## 13. Грабли, на которые уже наступали

| Грабли | Как обойти |
|---|---|
| `openpyxl` теряет диаграммы книги | писать листы только через zip |
| В JS `\w` не ловит кириллицу | явные классы `[А-Яа-яЁё]`, пробел как `[ ]+` |
| `calc.html` без `</body>` | скрипты вставлять в конец файла |
| Правило `.пункт .пункт` перебивало `.пункт.терм` | ограничено до `.пункт .пункт[data-таб]` |
| Второй массив справочника в отчёте жил своей жизнью | всё переносит `справочник_в_отчёт.py` |
| Скрипт читал лист, который сам же переписал | читать по заголовкам столбцов, а не по номерам |
| Прототипы в `Веб/Части/` расходятся с рабочими файлами | либо генератор, либо `Архив` |

## 14. Перейти в новую сессию без потери контекста

1. Обновить `Документация/Переезд_между_сессиями/ТОЧКА_ПРОДОЛЖЕНИЯ.md`:
   активная задача, последний завершённый шаг, открытый вопрос, следующее
   действие и результаты проверок.
2. Запустить интеграционную проверку, сверку глоссария и 15 сценариев Excel.
3. Собрать передачу:
   ```bash
   python3 Инструменты/собрать_передачу_сессии.py
   ```
4. Передать новой сессии файл:
   ```text
   Архив/Передача_между_сессиями/Счётикс_передача_АКТУАЛЬНАЯ.zip
   ```
5. Отправить по очереди шесть промптов из
   `Документация/Переезд_между_сессиями/02_ПРОМПТЫ_ДЛЯ_НОВОЙ_СЕССИИ.md`.
6. Не разрешать правки до успешного экзамена этапа 5.
7. После продолжения снова обновлять точку после каждого завершённого действия.

Исторические файлы передачи удалены из краткосрочного архива; действующий
протокол находится только в `Документация/Переезд_между_сессиями/`.
