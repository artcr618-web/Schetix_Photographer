### III.1 Блок 04 (REPORT-B030): кольцо месячного дохода — устройство после 24.09

Пять направлений вместо четырёх. Код — строки 6040–6260.

```js
var МЕС=11, hr=d.rateWork!=null?d.rateWork:0;
var НАПР=[                                    // порядок = обход по часовой от 12 часов
 {n:'Как отдел продаж',     ч:d.clT? …        c:'#E1306C', img:'продажи',     chip:1},
 {n:'Как отдел маркетинга', ч:d.promo,        c:'#3B82F6', img:'маркетинг',   chip:2},
 {n:'Как управленец',       ч:d.mgmtT,        c:'#0F766E', img:'управляющий', chip:4},  // 24.09
 {n:'Как бухгалтер',        ч:d.accT,         c:'#8B5CF6', img:'бухгалтер',   chip:3},
 {n:'Как фотограф',         ч:d.sh+d.post,    c:'#21A038', img:'фотограф',    chip:0}];
var эфф=Σч;  var k=1+(d.idle+d.fmT)/эфф;      // 24.09: управления в k больше нет
о.руб = hr*о.ч*k/МЕС;  итог = Σо.руб;
```

**Инвариант (выведен и проверен численно):**
`hr = rateWork = Ny×11/12 / workHours`, а `эфф + idle + fmT = NT + idle = workHours`,
поэтому `итог = hr×workHours/11 = Ny/12` — **множители 11 и 12 сокращаются**.
Центр кольца всегда равен доходу на руки за месяц; база: `1 322 592/12 = 110 216 ₽`.

Если бы `mgmtT` остался в `k` и одновременно стал сектором, управление вошло бы дважды —
именно это правило и зафиксировало «ПРАВИЛО_ДИАГРАММА…»: «`mgmtT` больше не входит в k,
иначе сумма плашек разошлась бы с центром».

Геометрия: сцена 1200×760, `CX=600, CY=340, RX=220, RY=110, DEP=46, HOLE=.53`;
поворот раскладки `t = -π/2 - π/6` (30° против часовой, слово 24.09 — «чтобы выноска к маркетингу шла короче»);
текст в центре не крутится. Точка-магнит выноски — середина кольца сектора:
`P(м, (1+HOLE)/2)`. Секторам уже 12° процент не рисуется.
Процент с сектора убран на десктопе (12.09) и возвращён только на мобильном (13.09, `.mon-pct`).
Центр вписывается в отверстие перебором кегля 34→12 с проверкой полуширины эллипса на верхней и нижней кромке
(`вписатьЦентр()`), поле 10px, зазоры 5/5.

Комментарий-баннер над блоком (строка 6040) **не обновлён**: он по-прежнему перечисляет
четыре роли — «фотограф, отдел продаж, отдел маркетинга, бухгалтер» — и не знает про управленца.

Три следствия, которые объясняют падения сторожа:

1. **Денежные поля — `type="text"`, а не `number`.** `min/max/step` у них декоративны:
   браузер их не применяет, их читает JS-валидатор (`data-limit-live`, `data-step-live`).
   К падению №23 это отношения не имеет (см. ниже) — но объясняет, почему пределы денег
   не работают как нативная валидация формы.
   **Настоящая причина №23 (`home_area`)**: тег поля полностью соответствует сторожу
   (`type="number" data-limit-live data-step-live min="1" max="1000" step="0.1"`), падают не атрибуты,
   а **литеральная строка подсказки шага**. Сторож ищет дословно
   `(el.id==='home_area'||el.id==='cab_area')?'0,1 м²':((el.id==='acq_rate'…`,
   а в `calc.html:4266` с 15.09 стоит
   `(el.id==='home_area'||el.id==='cab_area')?'0,1 м²':(el.id==='mgmt_amt')?'1 час':((el.id==='acq_rate'…` —
   добавилась ветка для поля управления. Все четыре текстовых подсказки про м² при этом на месте.
2. **Шаги времени — 1/60 часа, не 0,5.** `post_ratio` и `client_time` имеют `step="0.0166"`
   (= 1 минута), а `client_time` ещё и `min="0.01666"`, `max="24"`.
   Сторож ждёт «0,5–72 с шагом 0,5» (№24) и «0–72 с шагом 0,5» (№25) — отсюда падения.
3. **`acc_per_quarter`: имя обещает квартал, множитель берёт недели.**
   В коде `accT = acc_per_quarter × NW`, где `NW = 43.8` недель. Книга считает `× 4` квартала
   (её контрольное `accT = 12` при значении 3). Предел в книге `max=500`, в форме `max=20`.

### IX.3 Хрупкость харнесса, о которой нужно помнить при любой правке констант

Харнесс вырезает константы **по литеральным маркерам**:

```js
const КОНСТ1 = срез(CJS, 'var FIX=', 'WM=11;');
const КОНСТ2 = срез(CJS, 'var WD=',  'DW=5;');
const КОНСТ3 = срез(CJS, 'var ND=WD-VAC-SICK', ';');
const КАТ    = срез(CJS, 'var CAT={', '\nvar EXC={');
```

Правка `WM=11` или `DW=5` в `calc.html` без правки маркера в харнессе даёт
«`MO is not defined`» и гейт падает целиком. Проверено прогоном.
Аналогично `функция(текст,'parts')` ищет буквально `function parts(x){` —
переименование параметра или пробел перед `{` ломают вырезание.

## Часть XIV. Состояние git в этой среде (важно для следующего сеанса)

Снято 24.09 после переноса документа в архив.

Песочница сохраняет **файлы рабочего дерева**, но не сохраняет внутренности `.git`:
`.git/config` оказался пуст (ремоут пропал), `HEAD` откатился на `93e253b`,
а объекты доставленного `97bc09f` исчезли из хранилища — при том что содержимое файлов
во внешнем дереве осталось от `97bc09f`.

Что сделано для восстановления (файлы проекта не правились):

1. `git remote add origin https://github.com/artcr618-web/Schetix_Photographer.git`
2. `git fetch origin` → `93e253b..97bc09f main`, ветки `interface`, `logic`
3. `git reset --mixed 97bc09f` — указатель и индекс приведены к коммиту,
   содержимое которого уже лежало в дереве

Итог: `HEAD = main = origin/main = 97bc09f`, `git diff HEAD` пуст,
единственный неотслеживаемый файл — этот снимок.

**Вывод на будущее:** в начале каждого сеанса проверять `git rev-parse --short HEAD`
и `git status --short`. Если `HEAD` снова откатился, а дерево новее — повторить три шага выше.
Коммит, сделанный внутри песочницы, может не пережить снимок среды: доставлять изменения
наружу нужно push-ем в тот же сеанс, а не рассчитывать на сохранённый `.git`.
