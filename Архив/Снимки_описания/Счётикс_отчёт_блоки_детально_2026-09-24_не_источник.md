## 3. Подтверждённые дефекты при каноне (управление выключено)

### Д1. Нулевая плашка управленца остаётся
- **Где:** `Веб/report.html:6058` `НАПР=[...{ч:mgmtT}...]`, `6114` `if(t1-t0<1e-6) return` пропускает сектор, но `6981` `НАПР.forEach` рисует плашку всегда.
- **Что видит пользователь:** плашка «Как управленец 0 ₽/мес 0.0% от общего дохода» с персонажем ростом 1,25.
- **Правило:** `ПРАВИЛО_ДИАГРАММА_И_РОСТ_ПЕРСОНАЖЕЙ.md:83` прямо предусматривает 0% → 1,25 высоты, «чтобы персонаж с нулевой долей остался читаемой фигурой», но не говорит, должна ли плашка скрываться. Логика `visIdx` для секторов уже скрывает сектор, для плашек — нет.

### Д2. Кружок-магнит и выноска в NaN
- **Где:** `monfig-svg` исходно 5 `circle cx=0 cy=0`, `разложитьПоКольцу()` переписывает координаты только для ненулевых секторов. `камТочки` читаются из разметки один раз (`9269`) и не обновляются после `точки[с.i]=...`.
- **Следствие:** при `mgmtT=0` пятый кружок остаётся в 0,0, `маршрут()` получает `NaN` из `getBoundingClientRect` плашки с нулевой высотой.

### Д3. Легенда и таблица недели не знают управление
- **Где:** `8036` `СКР` без `mgW`, `8062` `ВТ` без `mgmtT`.
- **Следствие:** при `mgmtT>0` пользователь видит цвет `#0F766E` в календаре без подписи.

### Д4. `fullTab` мёртв
- **Где:** `7430` `var ft=$('fullTab')`, элемента с таким id нет в файле (проверено в `93e253b` и `97bc09f`).
- **Следствие:** 93 строки детальной таблицы времени (`rows.push(trow('Часов на управление делом',...))`) никогда не попадают в DOM. В jsdom `document.getElementById('fullTab')` = null в обоих мирах.

### Д5. `directFrameCosts` отсутствует в `d`
- **Где:** `9692-9694` `if(d.directFrameCosts>0)`, в `calc.html` 0 вхождений, в `d` (103 поля) нет.
- **Следствие:** блок B023 «Сколько стоит кадр» всегда считает по запасной ветке (через `shutterLife`/`depShoot`).

### Д6. Шкала роста — документ vs код
- **Док:** `1,25 + 3,75×доля`, макс 5.
- **Код:** `1,25 + 2,75×доля`, макс 4.
- **Открытый вопрос в доке §13:** «шкала 100%=4 и кольцо RX=220 геометрически несовместимы на 1440px». Код уже на 4, шапка дока ещё на 5.

### B028 `накопления` — «Что накопится при этой ставке»

**JS:** `Веб/report.html: ~9840-9900` (блок инвестиций, обрезан в логе, но логика):

**Связь с управлением:** нет. Инвестиции — денежные, управление — временное. Поэтому B024 не меняется при `mgmtT=0`.

### B029 `mpHost` / `mpZero` — «Доля чистой прибыли»

**JS:** `Веб/report.html:9811-9870`

```js
var m=window.PHR_PROFIT_Y?window.PHR_PROFIT_Y(Д):(+Д.fundY||0);
if(m>0){ host.innerHTML = баннер прибыли }
else { zero.innerHTML = баннер «Доля чистой прибыли не заложена» }
```

- `PHR_PROFIT_Y` = `суммаЧистойПрибыли(d)` — из `fundY` вычитается `суммаБуфера(d)` (буфер ликвидности). `fundY` зависит от `fund_on` (в живом дефолте выключен → `fundY=0`).
- При живом дефолте `fund_on` без `checked` → `fundY=0` → `m=0` → показывается жёлтый баннер в `#mpZero`: «Доля чистой прибыли не заложена / Ваше дело работает в ноль».
- При DEMO `fund_on` был `checked` в старой разметке? В `93e253b` `fund_on` имел `checked`, в `97bc09f` — нет. Поэтому DEMO показывает прибыль (если `fundY>0`), а живой — ноль. Это ещё одно расхождение DEMO vs LIVE, не связанное с управлением, а с `fund_on`.

**CSS:** `#mpHost:has(#mpBody:empty){display:none}` — пустой узел не занимает место. При нуле показывается `#mpZero`, при прибыли — `#mpHost`.

**Связь с управлением:** нет прямой, но `fundY` считается от `R` (выручки), которая зависит от `rateHour`, а `rateHour` зависит от `mgmtT` (через `pool`). Поэтому при `mgmtT=0` `R` выше (1 261 440 vs 1 156 320), но `fundY` всё равно 0, т.к. `fund_on` выключен.

## 15. Печать и PDF (B001, B003, B030, B008)

**Механизм:** `Веб/report.html:5476-5600` `установитьПечатнуюШапку(mode)` — генерирует SVG-колонтитулы с данными `d.Ny/12`, `d.rateHour`, датой. Передаётся через `@page { @top-left { content: url(data:image/svg+xml;base64,...) } }`, чтобы печататься и при выключенной опции «Фоновая графика».

**Пороги:**

- B030 кольцо: десктоп от 821px, мобильный ≤820px — `monfig-svg` скрыт, проценты показываются через `.mon-pct`.
- B008 календарь: десктоп от 721px (камера и инвестиции) и 821px (кольцо дохода).
- При `window.ПЕЧАТЬ_PDF` (Chromium `--print-to-pdf` держит окно 780px) пороги игнорируются — всегда десктопная раскладка, иначе блок 04 выходил пустым (замер 12.09).

**Что проверено в jsdom:** `matchMedia` замокано как `false`, поэтому в пробе выноски получили `NaN` — в реальном браузере на ширине >820px они строятся корректно. Нулевая плашка `monC4` с `NaN` — не артефакт мока, а реальный дефект при `mgmtT=0`, т.к. `getBoundingClientRect` плашки с нулевой высотой даёт `NaN` в расчёте маршрута.
