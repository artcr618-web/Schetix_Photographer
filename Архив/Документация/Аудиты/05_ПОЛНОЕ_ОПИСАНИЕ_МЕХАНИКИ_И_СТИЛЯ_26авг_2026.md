# 1. ЧТО ЭТО ЗА ПРОДУКТ

СЧЁТИКС считает **юнит-экономику одного часа съёмки**. Пользователь заполняет
анкету, получает отчёт: сколько должен стоить час его работы, чтобы после всех
расходов, налогов и комиссий на руках остался желаемый доход.

Ключевые свойства:

- **Всё считается в браузере.** Бэкенда нет. Один расчёт — функция `calc()`
  в `Веб/calc.html`.
- **Отчёт ничего не досчитывает.** Он получает готовый плоский объект и только
  раскладывает его по блокам. Это правило `RULE-001` из реестра правил.
  (Из него есть одно фактическое исключение — см. раздел 12.1.)
- **Продукт бесплатный на входе**, монетизация — платное скачивание отчёта
  (лист `10_Монетизация`: 490 ₽ прямая цена, 169 ₽ по реферальной ссылке).
- **Ниша пока одна** — фотографы. В коде это зашито одной переменной
  `var PROF='фотографа'`, подготовленной под расширение на другие профессии.

Продукт состоит из четырёх файлов: три HTML-страницы и книга Excel.

# 3. ТРИ ИСТОЧНИКА ПРАВДЫ

Это центральный принцип архитектуры. Каждая сущность объявлена ровно один раз.

| Что | Единственный источник | Кто потребляет |
|---|---|---|
| **Расчёт** | `function calc()` в `Веб/calc.html` | отчёт, детализация, книга 06b |
| **Названия** | словарь `СПРАВОЧНИК` в `Инструменты/таблицы_прототип.py` (84 записи) | анкета, отчёт, генераторы |
| **Понятия** | лист `01_Глоссарий` книги (138 записей, нумерация до 137) | справочник, «Состав», паспорта |

Плюс три правила, оформленные в `16_Реестр_правил`:

- **RULE-001 · Единственный источник расчёта.** Нужен показатель — считать
  в `calc()` и передавать готовым. Оболочки не создают параллельную математику.
- **RULE-002 · Точность и показ.** Полная точность внутри, округление до рубля
  при выводе. Округлённое не возвращается в формулы.
- **RULE-004 · Эффективный ноль.** Выключенный параметр остаётся в структуре
  и даёт нулевой вклад. Никаких альтернативных формул под каждое сочетание галочек.

## Правило потока данных

```
Анкета (calc.html)
  │  calc() → плоский объект d (105 полей)
  │  saveReport(): localStorage['phc_report'] = JSON
  │  запасной путь: reportLink(d) → report.html?data=<base64>
  ▼
Отчёт (report.html)
     loadData(): читает ?data= первым, затем localStorage
     нет ни того ни другого → DEMO-набор
     parts(d) → 14 сегментов кольца
     render() → раскладывает d по блокам
```

Состояние анкеты живёт отдельно: `localStorage['phc_state']` — чтобы человек
мог вернуться и дозаполнить. Ключи `phc_thx_liked` и `phc_thx_paid` — окно
благодарности и признак оплаты.

## 4.1 Типы управляющих элементов

Различаются по смыслу и обрабатываются разными правилами:

- **Обратная галочка** «Не учитывать этот блок» (`data-exc`, массив `EXC`) —
  `RULE-006`. Снята — блок участвует, установлена — все результаты блока нули,
  но введённые значения сохраняются для повторного включения.
- **Прямая галочка** (фонды, резервы) — `RULE-005`. Снята — ноль,
  установлена — работает.
- **Переключатель ветки** (radio/select: рабочее место, сайт, учёт) —
  `RULE-007`. Считается активная ветка, вклад остальных — ноль.
- **Контекстная галочка** `own_home` — `RULE-010`. Показывает рекомендацию,
  но **не обнуляет** стоимость жилья.
- **Управляющая галочка** `tax_auto` — `RULE-009`. Не денежный параметр,
  а способ выбора режима. Блокирует ручные настройки, повторный клик отпускает.
- **`tax_off`** «работа без оформления» — `RULE-017`. Обнуляет `RT`,
  весь остальной расчёт идёт по общей схеме.

## 4.2 Каталоги расходов

Позиции по умолчанию живут в двух местах и обязаны совпадать буквально:
объект `CAT` в `calc.html` и лист `03_Каталоги` книги (39 строк).

Годовая сумма позиции считается одинаково в обоих местах:

```
если задан срок службы (лет):   ₽/год = стоимость / срок      → амортизация
иначе:                          ₽/год = стоимость × платежей  → регулярный платёж
                                где платежей: Год=1, Квартал=4, Месяц=12
```

Восемь форм: `Form001` съёмочная техника · `Form002` офисная ·
`Form003` подписки · `Form004` ПО разово · `Form006` обучение ·
`Form007` банк · `Form010` реклама · `Form013` обустройство места.

## 5.5 Налог как честная функция выручки

Это место переписывалось: раньше база для УСН 15 и АУСН 20 бралась
от желаемого дохода и почти не зависела от выручки — из-за этого не сходилась
точка безубыточности, а сравнение режимов сравнивало одинаковые числа.

```js
function взносыОт(база){ return FIX + min(max(0, база-THR)*.01, CAP) }

function taxOf(Rx){
  if (БЕЗ_НАЛОГОВ) return 0;
  if (Rx <= 0) return 0;
  if (rg.indexOf('npd')===0) return Rx * RT;                    // 4 / 5 / 6 %
  if (rg==='usn6'){ var в6=взносыОт(Rx);
                    return max(0, Rx*.06 - в6) + в6 }           // вычет взносов
  if (rg==='ausn8') return Rx * .08;
  var б = max(Rx*(1-a) - C, 0);
  if (rg==='usn15'){
    var в = FIX;
    for (var i=0;i<12;i++){ в=взносыОт(б); б=max(Rx*(1-a)-C-в,0) }   // сходимость
    return max(б*.15, Rx*M15) + в;                              // минимальный налог
  }
  return max(б*.20, Rx*M20);       // АУСН Д−Р: взносов у ИП без работников нет
}
```

Два тонких места:

1. **Круговая зависимость УСН 15.** Взносы уменьшают базу (п. 1 ст. 346.16 НК),
   а сами зависят от базы. Решается 12 итерациями до сходимости.
2. **Минимальный налог.** Для Д−Р режимов налог не может быть меньше
   1 % (УСН) или 3 % (АУСН) от выручки.

### НПД раскрывается по заказчикам

```js

  rg = кто==='phys' ? 'npd4' : (кто==='jur' ? 'npd6' : 'npd5');
```

лиц, 6 % с компаний, смешанным берётся 5 % — середина.

## 5.6 Выручка — численный поиск, а не формула

**Ключевое архитектурное решение.**

```js
function выручкаПод(цель, доля){
  var d = (доля===undefined) ? D : доля;
  if (d <= 0) return 0;
  var lo=0, hi=1e9, m;
  for (var i=0;i<90;i++){
    m = (lo+hi)/2;
    if (m*d - C - taxOf(m) < цель) lo=m; else hi=m;
  }
  return lo;
}
```

**Почему делением пополам.** У налога есть изломы — минимальный налог,
потолок допвзноса, вычет взносов — и одной формулой их не описать.
90 итераций дают точность заведомо выше рубля. Тот же приём применён в отчёте.

```js
var R_ = (sh>0) ? выручкаПод(Ny) : 0;      // 2 042 534,97 ₽/год
var taxAll = taxOf(R_);                     //   102 126,75
var aq = R_ * a;                            //    55 148,44
var totalExpenses = C + taxAll + aq;        //   719 942,97 ₽/год
```

Если съёмочных часов не осталось, считать нечего: выручка нулевая, анкета
показывает подсказку и не пускает в отчёт (`RULE-008`, тест № 17).

**«Всего расходов»** — утверждённая группа: Финансовые расходы плюс Налоги
и Эквайринг. Резервный фонд и компенсация Инвестиционного времени **не входят**.
Решение 25.08 закрыло расхождение 719 942,97 против 441 255,19.

## 7.2 Функция `parts()` — 14 сегментов кольца

Единственная вычислительная функция отчёта, и она **не считает деньги заново** —
она раскладывает уже готовые величины по секторам:

```js
function parts(x){
  var work = x.workHours || ((x.NT||0)+(x.idle||0));
  var spend = (x.Ny||0)*11/12;
  var hr = x.rateWork != null ? x.rateWork : (work>0 ? spend/work : 0);
  var vac = x.vacY != null ? x.vacY : (x.Ny||0)/12;
  ...
  return [hr*x.sh, hr*x.post, hr*x.clT, hr*x.promo, hr*x.accT, hr*(x.fmT+x.idle),
          dS+dO+dP, vA+dW, vR+vB+vC+vS+dR+dE+depRest+varRest,
          x.taxAll, x.aq, x.fundY||0, x.discY||0, vac];
}
```

Порядок секторов: 6 доходных (съёмка, обработка, клиент, продвижение, учёт,
резервы времени) · 3 расходных (техника и ПО, реклама и сайт, прочие расходы) ·
налоги · эквайринг · фонд развития · запас на скидку · отпуск.

`depRest` и `varRest` — страховочные остатки: если сумма детальных строк меньше
общей группы, разница не теряется, а падает в строку «прочие». Это защита
от потерянного расхода при добавлении новой формы.

Тождества, которые проверяются: сумма всех 14 сегментов = выручка ·
доходные сектора = доход без отпуска · сектор отпуска = месячный доход.

## 7.4 Вторая налоговая модель в отчёте

**Это единственное фактическое исключение из RULE-001.**

В отчёте живут два налоговых блока — `TX0` (строка 3513) и `TXC` (строка 4015),
с собственными функциями `налог0()`, `netNPD()`, `netUSN6()`, `netUSNDR()`,
`netAUSND()`, `базаДР()`. Всего около 40 упоминаний.

Комментарий в коде объясняет назначение честно:

> Точка безубыточности. Раньше отчёт считал её самостоятельно и мог расходиться
> с анкетой в ветках фондов, собственного сайта и отключённых налогов.
> Теперь основной источник — готовые `Rb` и `rateZero` из `calc()`. Налоговые
> функции ниже остаются для текущего сценария, таблицы режимов и запасного
> чтения старого JSON без поля `Rb`.

То есть дублирование **сознательно сокращено, но не устранено**: осталось
для таблицы сравнения семи режимов (блок 07), которой нужны величины
по всем режимам сразу, а `calc()` отдаёт только выбранный.

Важная деталь — ставка эквайринга больше не зашита:

```js
var AQФАКТ = (d.R>0 && d.aq>=0) ? d.aq/d.R : 0.027;
```

Прежде в отчёте стояли жёсткие 2,8 % против 2,7 % в анкете — расхождение
на 0,1 п. п. Теперь ставка восстанавливается из переданных данных.
Охраняется проверкой № 49.

Константы `TXC` содержат актуальные лимиты 2026: НПД 2,4 млн · АУСН 60 млн ·
УСН 490,5 млн (450 млн × дефлятор 1,090, приказ Минэкономразвития № 734
от 06.11.2025) · порог НДС 20 млн.

```
    ▼           ▼           ▼          ▼         ▼
  hero      parts(d)    таблицы    сценарии   режимы

            (те же
            сегменты)
```

Три точки, где блоки обязаны сходиться:

1. **`parts(d)`** питает и кольцо блока 01, и три кольца блока 04 —

3. **`Rb` и `rateZero`** нужны блоку 04 (кольцо «В ноль») и блоку 06.

## 12.5 Стоп-точка: три себестоимости часа

Подтверждаю расхождение, зафиксированное в карте как отложенная стоп-точка
«понимание расходов». В коде живут три разные величины для одного понятия:

| Величина | Формула | Значение |
|---|---|---|
| `costHour` — «себестоимость часа съёмки» | `totalExpenses / sh` | **3 323,84 ₽/ч** |
| Ставка в ноль (честная безубыточность) | `Rb / sh` | **2 814,44 ₽/ч** |
| Себестоимость по глоссарию (без налогов) | `C / sh` | **2 598,19 ₽/ч** |

Разница между первой и второй — 509 ₽ — возникает потому, что `costHour`
берёт налоги и эквайринг **от полной выручки**, то есть как будто в точке
безубыточности мы платим налоги с полной загрузки. Точка безубыточности
считает проценты от самой себя.

От этого зависит `markup = rateHour/costHour − 1 = 183,7 %` — наценка считается
от самой спорной из трёх величин.

Блокирует расчёты № 26 и № 27 реестра.

## 12.12 Генератор `подсказки.py` неработоспособен

**Самая опасная из находок второго прохода.**

Скрипт содержит словарь `СЛОВА` — 34 понятия и регулярные выражения, по которым
в анкете подчёркиваются знакомые термины. Перед записью он сверяет словарь
со `СПРАВОЧНИКОМ`:

```python
нет = [т for т in СЛОВА if т not in СПРАВОЧНИК]
if нет:
    raise SystemExit('нет таких записей в справочнике: ' + ', '.join(нет))
```

В словаре осталась строка `'Минимальный выезд'` (строка 61), а понятие
переименовано 25.08 в «Минимальный заказ». Скрипт **падает с кодом 1
до единой записи в файл**.

При этом в самой анкете подсветка актуальна: 34 слова, среди них
«Минимальный заказ», «Минимальный выезд» отсутствует. То есть
**блок в `calc.html` правился помимо генератора** — прямое нарушение
правила «править источник, а не представление».

Последствия: любая правка справочника не доедет до анкеты; при попытке
перегенерации человек получит ошибку, смысл которой не очевиден.

Лечится одной строкой — заменой ключа на «Минимальный заказ» и регулярного
выражения на `минимальн[а-яё]+[ ]+заказ[а-яё]*`. Требует вашего слова,
поэтому не тронуто.
