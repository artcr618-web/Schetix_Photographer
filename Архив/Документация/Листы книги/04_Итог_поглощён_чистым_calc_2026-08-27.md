# 04_Итог — аудит и поглощение чистым calc

Дата: 27.08.2026  
Задача: З-041

## Вывод

`04_Итог` не является источником методики или исходных данных. Это производный
свод выбранного налогового режима, времени, расходов и контрольных проверок.
Уникальных входных значений на листе нет.

Старый лист сохраняется только внутри контрольной книги до общего переключения.
В чистую книгу отдельным листом не переносится.

## Что было на листе

- 56 строк, 3 колонки;
- 44 формулы;
- 12 главных финансовых результатов;
- иерархия времени;
- свод расходов;
- блок сравнения текущей и желаемой ставки;
- 11 самопроверок.

## Куда перенесено

### Финансовые результаты

| Старый показатель | Чистый источник |
|---|---|
| Ставка часа съёмки | `rate_hour_model` / `d.rateHour` |
| Стоимость проекта | `project_price_model` |
| Базовая ставка | `base_rate` / `d.rateWorkFull` |
| Выручка за год | `revenue_target` / `d.R` |
| Выручка в месяц | `revenue_month_model` |
| Налоги и взносы | `tax_target` / `d.taxAll` |
| Эффективная налоговая нагрузка | `effective_tax_load` |
| Точка безубыточности | `revenue_break_even` / `d.Rb` |
| Всего расходов | `total_expenses_model` / `d.totalExpenses` |

Важно: старая «Базовая ставка» совпадает с `d.rateWorkFull`, то есть
`Выручка / эффективное рабочее время`. Она не равна `d.rateWork`, который
показывает доход на руки за рабочий час по другой базе.

### Время и расходы

Все строки времени и расходов уже находились в именованных строках `calc`:
`net_time`, `side_time`, `fm_time`, `project_pool`, `core_time`,
`shooting_time`, `post_time`, `client_total`, `investment`, `variable_costs`,
`total_costs` и другие. Второе зеркало не создавалось.

### Текущий сценарий

Старая формула «Остаётся на руки» совпадала с HTML только в исходном сценарии.
В чистый `calc` перенесён полный актуальный состав из `calc.html`:

- `revenue_current`;
- `tax_current`;
- `acquiring_current`;
- `current_fund_model`;
- `current_discount_model`;
- `current_self_site_model`;
- `current_costs_total_model`;
- `current_result_model`;
- `current_income_model`;
- `current_loss_model`;
- `current_is_loss_model`;
- `rate_difference_model`;
- `income_gap_model`.

Текущий убыток не обрезается до нуля.

### Самопроверки

Проверки иерархии времени, безубыточности, налоговых режимов, лимитов,
эффективных нулей и текущего результата уже выполняет штатный
`Инструменты/проверить.py`. Их не нужно хранить вторым табличным блоком.

## Входящие зависимости старой книги

Прямые формульные ссылки на `04_Итог` оставались только в
`06b_Отчёт_полный`. Они будут заменены при сборке нового `Полный_отчёт`.

## Контроль

Девять сопоставимых значений старого листа сверены с настоящим `calc()`:
ставка часа съёмки, стоимость проекта, Базовая ставка, годовая и месячная
Выручка, Налоги, эффективная налоговая нагрузка, Точка безубыточности и
текущий результат. Расхождений нет.

Воспроизводимый инструмент:

```text
Инструменты/поглотить_04_итог_чистым_calc.py
```
